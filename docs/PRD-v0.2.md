# Glint PRD v0.2

- 文档状态：Draft，v0.2 已收敛
- 日期：2026-10-19
- 产品：Glint
- 英文定位：English beside your words.
- 平台：macOS 14+，Apple Silicon
- 产品性质：个人工具 / 小范围验证，不做账号、付费和云同步
- 关联 Demo：`/Users/alone/code/PinyinLensDemo`
- 一句话定义：在苹果拼音候选栏出现时，对当前蓝色高亮的焦点候选显示一行英文；单词显示英文对应词，短句显示自然翻译。

## 0. TL;DR

Glint 不替换输入法，而是在苹果拼音候选栏旁边加一层英文对照。

核心规则：

- 产品由一个**主窗口**和菜单栏 HUD 组成；主窗口负责模式、插件、权限和预览。
- 只处理**当前焦点候选**，不处理全部候选。
- 单词/短语只显示**最常用的一个英文对应词或短语**，不显示词性、释义、例句。
- 短句显示**自然的英文翻译**。
- 只显示**一行**，不发音、不收藏、不保存历史、不做复习系统。
- 默认“智能模式”：先查离线词典，未命中或判断为短句时使用本地翻译模型。
- 词典和翻译模型统一为同一套**可下载插件体系**；第一版只提供官方预设，安装包不带模型。
- 歧义、低置信或没有可靠结果时**不显示 HUD**，运行时不弹窗。
- 8GB Apple Silicon 支持词典 + 轻量翻译模型；高质量模型建议 16GB。
- 第一版只支持 Apple Silicon，所有推理本地完成。

## 1. 背景与问题

中文母语者在日常输入中文时，经常遇到“我知道这个概念，但不确定英文怎么说”的瞬间。现有做法通常是：

- 切到词典 App 或网页查词；
- 选中文本后调用翻译工具；
- 复制到 AI 聊天窗口里问；
- 直接放弃，继续用中文表达。

这些动作都会打断输入，而且查到的内容往往是一大段释义，不是用户当下需要的那个英文词。

苹果拼音的候选栏本身就是用户注意力所在的位置。如果能在焦点候选旁边直接显示一行英文，用户不需要切换 App、不需要选中文本、不需要改变输入习惯，就能获得一次轻量的英文曝光。

## 2. 产品目标

### 2.1 目标

1. 在用户输入中文时，对焦点候选提供**即时、单行、可直接使用**的英文。
2. 保持苹果原生输入体验：不替换输入法、不改变候选排序、不抢焦点。
3. **默认全局生效**：任何 App 中使用苹果拼音都尝试显示，不依赖固定 App 列表；无法识别的 App 静默跳过。
4. 单词优先给英文对应词，短句给自然翻译；不把“英文释义”当成产品输出。
5. 支持离线词典和本地翻译模型两种能力，用户可自行下载、切换、删除。
6. 安装包保持轻量；模型按需下载；下载完成后推理完全离线。
7. 默认不保存输入内容、不监听键盘、不联网推理。
8. 按个人工具做：不做账号、付费、云同步、遥测和商业化支持。

### 2.2 非目标

- 不做自研输入法，不接入 InputMethodKit / librime。
- 不做生词本、复习、间隔重复、学习统计。
- 不做发音、TTS、音标。
- 不做英文释义、词性、例句、同义词树。
- 不做账号、云同步、社交、排行榜。
- 不做整段文档翻译或全文对照。
- 第一版不支持第三方输入法（搜狗、微信输入法、百度等）。
- 第一版不支持 Intel Mac。
- 第一版不以 Mac App Store 为主要分发渠道。
- MVP 不做应用白名单/黑名单；默认全局生效，过滤策略在后续版本再定。
- MVP 不在运行时弹窗；歧义、低置信、无结果、翻译失败都静默隐藏 HUD，只在主窗口/菜单栏显示状态。
- MVP 不开放任意第三方模型导入；只提供官方预设插件。

## 3. 目标用户

### 3.1 主要用户

- 中文母语者；
- 英语水平大约 B1–B2 或以上；
- 每天在 Mac 上大量输入中文；
- 使用苹果拼音「Pinyin – Simplified」；
- 希望在打字过程中被动接触英文表达，但不想切换工具或做额外学习任务。

### 3.2 典型场景

- 写工作消息时，想把“算法”“对齐”“复盘”换成英文表达；
- 写文档时，想确认某个中文短语的地道英文；
- 聊天时看到候选“你好吗”，想知道自然英文是 “How are you?”；
- 在任何使用苹果拼音的 App 中，都不想打断输入，也不想把内容复制到外部工具。

### 3.3 不服务的用户

- 主要使用第三方输入法的用户；
- 需要完整词典释义、例句、发音的用户；
- 需要系统化课程、复习计划、单词本的用户；
- 需要整段翻译或写作润色的用户。

## 4. 核心用户故事

1. 作为用户，我输入 `nihao`，焦点候选是“你好”，候选栏旁边显示 `hello`。
2. 作为用户，我输入一个短语候选“你好吗”，旁边显示 `How are you?`。
3. 作为用户，我输入一个成语或固定短语，词典命中时显示对应的英文短语。
4. 作为用户，我选择“智能模式”，词典没有命中时自动使用本地翻译模型，而不是直接显示“未收录”。
5. 作为用户，我可以下载、切换、删除词典插件和翻译模型插件。
6. 作为用户，我不希望它记录我输入过什么，也不希望它把我的文本发到网络。
7. 作为用户，当我在密码框或安全输入场景中，提示层完全不出现。

## 5. 产品原则

1. **原生优先**：不改变候选栏、不改变按键、不抢焦点。
2. **一次一行**：只显示当前焦点候选对应的英文，不展示释义列表。
3. **默认快速**：词典优先，模型只做兜底。
4. **本地优先**：OCR、词典、模型推理都在本机完成。
5. **不猜**：没有可靠结果时显示“未收录”或提示安装插件，不编造。
6. **最小权限**：屏幕录制 + 辅助功能；不使用输入监控，不记录键盘。
7. **可插拔**：词典和翻译模型都是可下载、可替换的能力，不写死在 App 里。

## 6. 功能需求

### 6.1 焦点候选识别

- 仅在当前输入源为苹果拼音 `com.apple.inputmethod.SCIM.ITABC` 时工作。
- 默认全局生效，不依赖固定 App 列表；任何 App 中只要 TIS、辅助功能和候选栏可用，就尝试显示。
- 如果某个 App 不暴露光标/控件 frame，或候选栏无法识别，静默跳过，不弹错误、不阻塞输入。
- 后续版本可以增加白名单/黑名单，但 MVP 固定为全局。
- 通过辅助功能获取焦点文本控件的光标位置和控件 frame。
- 通过 ScreenCaptureKit 截取光标附近的候选栏区域。
- 检测候选栏中的蓝色高亮胶囊，裁剪后用 Vision OCR 识别。
- 只处理高亮胶囊里的文本；不读取文本控件正文。
- 候选变化、提交、失焦或切换输入法时，及时刷新或隐藏。
- 安全输入（密码框、终端安全输入等）直接跳过。
- 当前只保证默认蓝色高亮；其他强调色、深色主题、特殊皮肤需要后续校准。

### 6.2 输出规则

#### 单词/短语

- 输出一行英文对应词或短语。
- 不输出词性、英文释义、例句、音标。
- 默认只给一个最常用对应词。
- 如果两个表达在词频和语义上几乎等价，可以用 `/` 连接，最多两个；仍保持一行。
- 示例：

```text
算法      → algorithm
计算      → calculate
复盘      → retrospective
你好      → hello
```

#### 短句

- 输出一行自然的英文翻译。
- 不做逐词直译，不解释语法。
- 示例：

```text
你好吗          → How are you?
今天天气不错    → The weather is nice today.
```

#### 无法处理

- 数字、emoji、纯符号、无法识别的候选：不显示面板。
- 歧义、低置信、词典未命中且没有可用翻译插件：不显示 HUD，不编造英文。
- 翻译失败：不显示 HUD；只在主窗口或菜单栏显示状态。
- 运行时不弹窗；系统权限提示除外。

### 6.3 模式与路由

用户可以在设置中选择三种模式：

| 模式 | 行为 |
|---|---|
| 智能模式（默认） | 词典高置信命中 → 词典；未命中、低置信或判定为短句 → 当前翻译插件；模型不确定/无插件 → 不显示 |
| 纯词典模式 | 只查词典；未命中或歧义 → 不显示；不调用模型 |
| 纯模型模式 | 所有候选都交给当前翻译插件；模型不确定 → 不显示 |

路由规则：

1. 先判断候选是否命中当前词典插件。
2. 命中且不是明显短句 → 使用词典结果。
3. 未命中或长度/标点表明是短句 → 使用翻译插件。
4. 用户选择纯模式时，严格按模式执行，不自动回退。
5. 没有安装任何插件或没有可靠结果时，HUD 不显示；主窗口/菜单栏显示插件状态，不弹窗。

词典命中不等于结果可信。候选是单字、词条有多个明显不同的英文对应词、或词典只能给出解释性长句时，智能模式应标记为 ambiguous，并交给翻译插件；没有翻译插件或模型也不确定时，不显示 HUD。

### 6.4 词典与翻译插件

#### 插件类型

- **词典插件**：提供中文词条 → 英文对应词/短语的快速查询。
- **翻译插件**：提供短句自然翻译，也可作为词典未命中的兜底。

#### 插件管理

- 插件列表显示：名称、类型、大小、质量等级、速度、最低内存、许可证、安装状态。
- 支持下载、校验、安装、切换、删除、更新。
- 下载完成后完全离线；推理不发起网络请求。
- 安装包不包含完整词典或模型，保持小体积。
- 首次启动提供引导，让用户选择并下载基础插件。
- 插件 manifest 和模型文件都要校验 SHA256。
- 词典和翻译模型统一为同一套插件体系：共用 manifest、PluginManager、安装目录和下载校验。
- 第一版只提供官方预设插件；用户可下载、切换、删除，不开放任意第三方模型导入。

#### 预设插件（候选）

| 插件 | 类型 | 体积量级 | 定位 |
|---|---|---|---|
| CC-CEDICT | 词典 | 十几 MB | 基础词典，默认安装 |
| OPUS-MT zh-en | 翻译 | 约 100–300MB | 轻量默认翻译，追求速度 |
| M2M100-418M | 翻译 | 约 450MB | 均衡备选，多语言 |
| Qwen3-4B 4-bit | 翻译/LLM | 约 2–3GB | 高质量可选插件 |
| Apple Translation | 系统翻译 | 0 插件下载；系统语言包可能需下载 | 可选，取决于系统可用性 |

具体模型版本、许可证、量化格式和体积在 M1 模型 spike 中确认。

### 6.5 HUD 显示

- 单行显示，不换行。
- 自动宽度，最大约 520pt；超长省略。
- 位于候选栏下方；空间不足时翻到上方。
- 不覆盖候选栏本身，不抢焦点，不改变当前候选选择。
- 候选稳定约 150–250ms 后出现；提交、继续输入、失焦后消失。
- 纯模型模式允许短暂显示“翻译中…”状态，但必须在一行内完成，不弹大卡片。
- 歧义、低置信、无结果或翻译失败时不显示；不弹窗。
- 默认无按钮；发音和收藏都不做。
- 支持浅色/深色外观；默认蓝色高亮。

### 6.6 主窗口

Glint 除了菜单栏 HUD，还需要一个完整的主窗口。它不是一次性的 Preferences 弹窗，而是用户打开 App 后看到的产品控制台。

窗口形态：

- 独立 `NSWindow`，左侧分组导航，右侧内容区；
- 参考 Bob/系统设置的分组侧栏，但不复制其视觉；
- 默认约 1120×720，最小约 960×640；侧栏 220–240pt；内容区可滚动；
- 透明标题栏、全尺寸内容、系统强调色、深色/浅色自适应；
- 关闭窗口只隐藏，不退出 App；后台监控继续。

侧栏结构：

| 分组 | 页面 | 内容 |
|---|---|---|
| 产品 | 概览 | 监控开关、当前状态、输入源、当前模式、插件/权限摘要 |
| 输入 | 显示与触发 | HUD 位置、稳定时长、最大宽度、实时预览 |
| 能力 | 插件与模型 | 词典插件 + 翻译模型；安装/更新/删除/切换、速度/质量/内存 |
| 安全 | 权限与隐私 | 屏幕录制/辅助功能状态、截取范围预览、隐私说明、日志 |
| 产品 | 关于 | 版本、更新、第三方许可证 |

页面要点：

- **概览**：顶部状态卡（全局监控中/已暂停）、开始/停止按钮、当前 App、当前输入源、模式选择（智能/纯词典/纯模型）、插件摘要、权限缺失提示。
- **显示与触发**：HUD 位置（自动/上方/下方）、候选稳定时长、最大宽度；用一个模拟候选栏 + HUD 做实时预览。
- **插件与模型**：上半部分是词典插件（当前版本、大小、安装/更新/删除、英文对应词策略）；下半部分是翻译模型（列表、默认插件、大小/速度/质量/最低内存/许可证、下载进度、删除、切换、智能模式回退顺序）。
- **权限与隐私**：屏幕录制/辅助功能状态卡、打开系统设置、真实截取范围预览、“不读取正文/不保存文本/不联网推理”的说明。
- **关于**：版本、更新、第三方许可证、项目链接。

第一版把词典和翻译模型合并为一个页面，避免侧栏过于稀疏；如果后续插件数量增加，再拆成两个独立页面。

布局草图：

```text
┌──────────────────┬────────────────────────────────┐
│ 概览              │ 插件与模型                       │
│ 显示与触发        │ ┌────────────────────────────┐ │
│ 插件与模型        │ │ 词典                        │ │
│ 权限与隐私        │ │ CC-CEDICT  [已安装] [更新]  │ │
│ 关于              │ └────────────────────────────┘ │
│                  │ ┌────────────────────────────┐ │
│                  │ │ 翻译模型                    │ │
│                  │ │ OPUS-MT   [使用] [删除]     │ │
│                  │ │ Qwen3-4B  [下载]            │ │
│                  │ └────────────────────────────┘ │
└──────────────────┴────────────────────────────────┘
```

窗口行为：

- 菜单栏提供“打开主窗口”；首次启动默认打开主窗口，而不是弹一个阻塞式欢迎框。
- 主窗口关闭后 App 继续驻留菜单栏，HUD 继续工作。
- 第一版只驻留菜单栏，不显示 Dock 图标。
- 通过 AppKit `NSWindow` + `NSHostingView` 承载 SwiftUI 内容；窗口生命周期由 AppKit 管，页面用 SwiftUI。
- 侧栏用 `NavigationSplitView` + `List(selection:)`；设置卡片用 `Form(.grouped)`/`Section`；不引入第三方 UI 组件库。
- 采用系统控件、SF Symbols、系统强调色和 `NSVisualEffectView`；视觉接近系统设置，而不是自造一套 UI 框架。

状态设计：

- 无插件：显示下载卡片和“下载后启用”按钮。
- 下载中：显示进度、暂停/取消、禁用删除。
- 权限缺失：主窗口顶部显示黄色提示条和“打开系统设置”。
- 模型超出内存：显示最低内存要求，禁用安装。
- 翻译失败：显示轻量错误状态，不把错误文本写进日志。

### 6.7 设置

设置是主窗口中的页面，不是独立的小弹窗。至少包含：

- 模式：智能 / 纯词典 / 纯模型；
- 词典插件：当前使用、下载、更新、删除；
- 翻译插件：当前使用、下载、更新、删除；
- 模型存储位置和占用空间；
- 离线状态；
- HUD 位置：自动 / 上方 / 下方；
- 候选稳定时长；
- 高亮颜色校准；
- 应用过滤（后续版本；MVP 不做白名单/黑名单）；
- 权限状态与重新授权入口；
- 隐私说明和日志开关；
- 关于与第三方许可证。

不包含：生词本、复习计划、发音、账号、同步。

### 6.8 权限与隐私

- 需要屏幕录制：截取候选栏区域。
- 需要辅助功能：读取光标位置和焦点控件 frame。
- 不需要输入监控，不监听键盘。
- 不读取文本控件正文，只读取光标位置和控件 frame。
- 不保存候选文本、翻译结果或输入历史；仅允许内存 LRU 缓存。
- 不记录按键、不记录剪贴板、不记录窗口标题。
- 安全输入场景自动跳过。
- 模型下载是唯一允许的网络行为；推理阶段不联网。
- 引导页必须提供“实际截取范围”的实时预览，让用户看到只截候选栏。

## 7. 非功能需求

### 7.1 性能目标

| 指标 | 目标 |
|---|---|
| 词典查询 p95 | < 50ms |
| OCR 单次 | < 50ms |
| 词典模式 HUD 出现 p95 | < 100ms |
| 模型首 token | < 300ms |
| 短句翻译完成 | < 600ms（30 字以内） |
| 空闲 CPU | < 2% |
| 翻译时 CPU | < 10% |
| 词典模式内存 | < 150MB |
| 轻量翻译插件内存 | < 1.5GB |
| 高质量插件内存 | < 6GB |

内存分级：

- 8GB Apple Silicon：支持词典模式和轻量翻译模型；
- 16GB 及以上：可下载高质量翻译插件；
- 下载前检查可用内存，不满足时禁用安装并提示最低要求。

### 7.2 准确性目标

- 焦点候选 OCR 准确率：支持 App 内 > 98%。
- 常用单词英文对应准确率：> 90%（人工评测集）。
- 短句自然度：人工 1–5 分评测，80% 以上样本 ≥ 4 分。
- 不允许出现明显中文、解释性长句或模型自我说明。

### 7.3 兼容性

全局策略：

- 默认全局生效，不依赖固定 App 列表；
- 任何 App 中使用苹果拼音都尝试显示；
- 无法识别的 App 静默跳过，不影响输入；
- MVP 不做白名单/黑名单；后续再定过滤策略。

验证目标（不是白名单）：

- macOS 14+；
- Apple Silicon；
- 苹果拼音「Pinyin – Simplified」；
- TextEdit、Safari、Chrome、VS Code、微信、Word；
- 默认蓝色高亮；
- 单显示器；多显示器作为 best effort。

暂不支持：

- Intel Mac；
- 第三方输入法；
- 自定义强调色/皮肤；
- 候选栏位于光标上方且远离文本框的特殊布局；
- 全屏游戏、远程桌面、虚拟机等特殊渲染环境。

### 7.4 安全与分发

- Developer ID 签名 + 公证；
- 直接下载分发，暂不上 Mac App Store；
- 插件模型只作为数据加载，不执行任意第三方代码；
- 固定运行时适配器；
- 所有下载校验 SHA256；
- 第三方词典/模型许可证随插件展示；
- 更新使用 Sparkle 或等价的安全更新机制。

## 8. 技术方案概要

### 8.1 数据流

```text
苹果拼音候选栏
  → TIS 判断输入源
  → Accessibility 获取光标/文本框 frame
  → ScreenCaptureKit 截取候选栏区域
  → 蓝色高亮检测 + Vision OCR
  → SmartRouter
  → DictionaryPlugin / TranslationPlugin
  → 单行 HUD
```

### 8.2 模块

- `InputContextMonitor`：TIS + AX 状态、光标位置、安全输入判断。
- `CandidateCapture`：ScreenCaptureKit 截取候选栏区域。
- `CandidateDetector`：蓝色胶囊检测 + Vision OCR + 文本清洗。
- `SmartRouter`：根据模式、词典命中、候选类型选择插件。
- `DictionaryPlugin`：CC-CEDICT/扩展词典查询，返回最佳英文对应词。
- `TranslationPlugin`：本地翻译模型推理，返回自然英文。
- `PluginManager`：manifest 解析、下载、校验、安装、删除。
- `ModelManager`：模型文件、运行时、内存检查、版本更新。
- `HUDController`：单行非激活面板，定位与自动隐藏。
- `MainWindowController` / `MainWindowView`：AppKit 窗口外壳 + SwiftUI 侧栏/页面；从菜单栏打开，关闭后隐藏。
- `AppPolicy`：应用过滤策略；MVP 固定 `.all`，后续扩展为白名单/黑名单。
- `SettingsStore`：模式、插件、HUD、隐私设置。
- `Diagnostics`：隐私安全的日志、延迟指标、错误状态。

### 8.3 运行时

- 词典：SQLite + CC-CEDICT；可选 ECDICT 反查/词频排序。
- 专用翻译模型：优先 CTranslate2 int8（OPUS-MT/M2M100）。
- 通用 LLM：优先 MLX（Apple Silicon），llama.cpp 作为备选。
- Apple Translation：作为可选系统插件，不强行依赖。
- OCR：Vision `VNRecognizeTextRequest`。
- 截取：ScreenCaptureKit。

### 8.4 线程与缓存

- 截取、OCR、翻译全部离开主线程。
- 主线程只负责 HUD 和设置 UI。
- 候选变化时取消旧请求，避免旧翻译覆盖新候选。
- 内存 LRU 缓存最近结果；不落盘。
- 模型常驻内存；词典使用 mmap/SQLite 读取。

```json
{
```

```text
~/Library/Application Support/Glint/
  plugins/
    dict-cedict/
      manifest.json
      dictionary.sqlite
    mt-opus-zh-en/
      manifest.json
      model/
  cache/
```

### 9.3 安全约束

- 不允许插件携带 dylib、脚本或可执行文件。
- 插件只能包含 manifest、模型权重、词库数据和固定格式的配置。
- 运行时由 App 内置的适配器提供。
- 下载必须校验大小、SHA256、版本和运行时兼容性。
- 删除插件时必须清理模型和缓存。

## 10. 成功指标

### 10.1 激活

- 首次启动完成基础插件下载的比例；
- 屏幕录制权限授予率；
- 辅助功能权限授予率；
- 首次成功显示 HUD 的比例。

### 10.2 使用

- 日活用户数；
- 每人每日 HUD 展示次数；
- 每人每日主动切换模式/插件的次数；
- 关闭监控或卸载的比例。

### 10.3 质量

- 焦点候选 OCR 准确率；
- 单词英文对应人工准确率；
- 短句自然度人工评分；
- “翻译错误/看不懂”反馈率；
- 模型输出中出现解释、中文、引号、长句的比例。

### 10.4 性能与信任

- HUD 出现 p95 延迟；
- 模型模式 p95 完成时间；
- CPU/内存占用；
- 打字速度影响（用户主观 + 小样本计时）；
- 崩溃率；
- 是否有任何文本被写入磁盘或发送到网络。

记忆强化本身很难用产品内指标直接衡量；MVP 不通过生词本或复习数据来证明价值。Beta 阶段可以做一次小样本回忆测试，但不作为首发阻塞项。

## 11. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 用户不信任屏幕录制权限 | 激活率低 | 引导页实时预览截取范围；明确不读正文、不存文本；只截候选栏 |
| 蓝色胶囊/候选栏 UI 变化 | 识别失败 | 版本化检测配置；颜色校准；OCR + 词典约束兜底 |
| 全局生效后 App 兼容性差异大 | 某些 App 无 HUD | 静默跳过；提供兼容性诊断；后续白名单/黑名单 |
| 词典只能给释义，选不出唯一英文对应词 | 单词结果不准确 | 词频/ECDICT 反查/人工 override；复杂词走模型 |
| 小翻译模型质量不够 | 短句翻译生硬 | 默认轻量插件 + 高质量插件可选；模型 spike 选型 |
| 本地 LLM 内存/延迟过高 | 低配 Mac 不可用 | 模型按需下载；显示最低内存；默认轻量翻译模型 |
| 插件下载/许可证复杂 | 合规和分发风险 | 官方预设插件；逐项核对许可证；manifest 展示 |
| 多显示器/全屏定位 | HUD 位置错误 | MVP 单屏；多屏 best effort；后续校准 |
| Apple 修改候选栏或系统翻译 API | 兼容性回退 | 版本检测；保留 OCR 路径；不依赖私有 API |
| 用户以为是输入法或全文翻译 | 预期错位 | 产品文案明确“焦点候选英文对照”，非翻译器/输入法 |

## 12. MVP 范围与验收

### 12.1 MVP 包含

- 苹果拼音焦点候选识别；
- 默认全局监控，不依赖固定 App 列表；MVP 不做白名单/黑名单；
- 单词/短语 → 一行英文对应词；
- 短句 → 一行自然英文翻译；
- 歧义/低置信/无结果时不显示 HUD，运行时不弹窗；
- 智能模式 + 纯词典 + 纯模型；
- CC-CEDICT 词典插件；
- 至少一个轻量本地翻译插件；
- 词典与翻译模型统一插件体系；v1 仅官方预设，支持下载/切换/删除；
- 带左侧分组导航的主窗口（概览/显示/插件与模型/权限/关于）；
- 8GB Apple Silicon 支持词典 + 轻量翻译模型；
- 单行 HUD；
- 屏幕录制 + 辅助功能引导；
- 安全输入跳过；
- 本地推理、无文本持久化；
- Developer ID 签名和公证。

### 12.2 验收标准

1. 默认全局监控；在 TextEdit、Safari、Chrome、VS Code、微信、Word 等代表性 App 中，苹果拼音候选出现时能显示 HUD，不需要手动添加 App 白名单。
2. 焦点候选为“你好”时显示 `hello`；为“你好吗”时显示 `How are you?`。
3. HUD 不抢焦点，不改变候选选择；提交后消失。
4. 词典模式 p95 < 100ms；模型模式 30 字以内 p95 < 600ms。
5. 安装包不含模型时 < 50MB。
6. 卸载/删除插件后，对应能力立即不可用，且不残留模型。
7. 在密码框/安全输入场景中不出现 HUD。
8. 日志中不出现候选文本、用户输入或翻译内容。
9. 主窗口可从菜单栏打开；关闭后 HUD 和监控继续工作；侧栏页面可正常切换。
10. 歧义、低置信或无可靠结果时不显示 HUD；运行时不弹窗。
11. 8GB Apple Silicon 可运行词典 + 轻量翻译模型；高质量模型在内存不足时禁用安装并提示 16GB。
12. 第一版只驻留菜单栏，不显示 Dock 图标。

### 12.3 MVP 不包含

- 生词本、复习、间隔重复、学习统计；
- 发音、音标、TTS；
- 英文释义、例句、词性；
- 第三方输入法；
- Intel Mac；
- 全文翻译；
- 账号、云同步；
- Mac App Store 首发。

## 14. 待讨论

1. 默认轻量翻译插件选 OPUS-MT 还是 M2M100？需要 M1 spike 决定。
2. 单词/短语是否允许两个同义表达用 `/` 连接？当前建议默认只给一个，极少数并列时最多两个。
3. 词典模式如何选择“最佳英文对应词”：ECDICT 反查 + 词频 + 人工 override，还是只做一个小型精编词表？
4. 第一版是否支持自定义系统强调色/深色主题？建议先默认蓝色，后续校准。
5. 多显示器/全屏是否作为 MVP 阻塞项？建议不作为阻塞项，但要做基本 best effort。
6. 模型下载的托管方式：自建 CDN、GitHub Releases，还是模型平台直链？
7. Apple Translation 是否作为“零下载”预设插件？需要验证 API 可用性和语言包。
8. 白名单/黑名单的产品形态与生效范围：全局默认，后续再定。
9. 高质量模型的具体版本和量化格式，需要在 M1 spike 中确认。
