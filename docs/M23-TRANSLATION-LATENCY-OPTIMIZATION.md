# M23 Translation Display Latency Optimization

- 日期：2026-10-22
- 范围：候选检测轮询、渐进结果、模型 warmup、取消路径和 HUD 进入动画

## 1. 目标

在不改变“候选停留后才启动翻译”语义的前提下，尽量减少停留确认后的固定
开销，并缩短一栏模式从开始翻译到首次可见结果的时间。

本轮不引入以下行为：

- 不监听键盘事件；
- 不为快速变化中的候选预启动模型；
- 不改变词典优先、模型优先及失败回退顺序；
- 不持久化候选文本或翻译结果。

## 2. 实现

- 候选停留下限从 80ms 调整为 50ms，默认值仍为 120ms。
- 活跃候选常规轮询为 24ms，并在接近停留截止点时按剩余时长调度最后一次轮询，
  避免固定轮询周期把 50ms 停留拖长到 72ms 以上；没有候选时仍使用低频轮询。
- 一栏模式最多接受 9 个可见候选，全部候选同时进入并发翻译任务。选中项结果到达
  时先发布完整候选槽位：选中项显示译文，其他项暂时显示占位，随后在同一 revision
  中继续原位补全。任务提交顺序把选中项放在第一位，以在底层单模型串行访问时优先
  保证当前选中项。
- `AppDelegate` 接受同一 revision 的渐进结果，只拒绝比当前展示更旧的 revision。
- HUD 将同一 revision 的渐进结果视为内容补丁，不重复播放淡化或窗口布局动画；
  首次入场期间只保留最新的待提交补丁，入场完成后再原子应用。
- HUD 保存相对候选行的左侧偏移；候选行移动超过 `8pt` 时跟随，小于阈值的抖动
  才被忽略。panel 宽度始终使用当前内容尺寸，不再让历史最大宽度参与定位。
- 翻译结果提交时读取最新候选几何，不在结果中复用停留开始时的旧位置；自动上下
  定位在一个会话内保持方向，只有当前方向放不下时才翻转。
- 8ms 内的 HUD 更新合并为最后一个快照，避免同一批 `selected` 与 `row` 结果
  依次绘制；HUD 内容在宿主视图中左对齐，可见胶囊保持当前内容的自然宽高，
  圆形外轮廓只由 SwiftUI `Capsule` 绘制。
- AX 候选读取偶发失败使用连续两帧确认；明确的组合结束、失焦和输入法切换仍立即
  隐藏，避免把瞬时读取失败误判为会话结束。
- MLX 模型加载完成后，使用固定文本执行一次最多 16 token 的静默 warmup，覆盖
  首次生成路径；warmup 不使用用户候选，也不进入缓存。
- 路由、模型运行时和具体推理引擎在关键入口检查任务取消。新候选到来后，旧任务
  即使已经排在 actor 后面，也会在执行入口立即退出，不再产生推理。
- HUD 首次进入淡入从 80ms 调整为 60ms，仍满足仓库规定的 80ms 上限。
- 新增脱敏日志 `phase=selected_ready`、`phase=row_ready` 和 HUD 可见事件，用于
  关联观察一栏模式首个可见结果及整行补全耗时。
- 增加候选变化、停留、路由、结果完成和 HUD 可见的关联延迟日志，采集方法见
  `M24-TRANSLATION-LATENCY-MEASUREMENT.md`。
- 单次多候选 MLX 批量请求已在探针中验证；3、6、9 项均慢于逐项请求，因此未接入
  正式路由，见 `M25-MLX-BATCH-TRANSLATION-EXPERIMENT.md`。
- OPUS-MT 与 Hy-MT2 的同机对照已完成；OPUS 快约 3–4 倍，但通用质量不足，
  见 `M26-OPUS-HYMT2-COMPARISON.md`。

## 3. 验证

定向测试：

- `GlintCore`：43 个通过；
- `GlintMac`：33 个通过；
- `GlintInference`：14 个通过；
- `GlintUI`：26 个通过。

完整回归：`./scripts/test.sh` 通过。

新增覆盖：

- 选中模式必须读取可见候选布局，以继续拒绝展开候选网格；
- 一栏模式最多 9 项，所有候选并发启动，并在选中项到达时先发布；
- 首帧渐进结果保留完整候选槽位，选中项先行，其他槽位等待补全；
- 模型首个结果发布后仍保留所有候选的最终展示项；
- 同 revision 使用原位补丁，新 revision 才进入过渡。

真实 App：

- `./scripts/dev.sh` 构建并启动成功；
- 启动准备包含当前 MLX 模型 warmup；
- 最近一次真实启动记录到 MLX warmup 用时 122.808ms；
- 只保留一个 Debug Glint 进程。

## 4. 尚缺的真实验收

当前活动输入源为 ABC，自动化测试无法生成真实苹果拼音候选。因此本轮没有获得
真实多行候选场景下从最后按键到 HUD 可见的 p50/p95。后续需要在苹果拼音下分别
记录 `选中`、`一栏`、缓存命中、Hy-MT2 和 OPUS-MT 的端到端延迟。
