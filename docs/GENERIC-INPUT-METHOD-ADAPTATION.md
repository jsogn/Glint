# 通用输入法与候选运行规则

Glint 不为每个输入法厂商复制一条读取链路。输入法只有匹配已验证的候选结构后，
才启用对应 reader；相同结构直接复用。

## 支持结构

| 能力 | 结构 | 高亮来源 |
| --- | --- | --- |
| 标准候选 | 宿主 `InputMethodCandidateList` | 父列表 `AXSelectedChildren` |
| `isolatedCandidateList` | 独立进程单行匿名 `AXList` | 无高亮，首候选降级 |
| `isolatedStyledText` | 独立窗口中的直接文本项 | 原生选中或唯一样式高亮 |
| `isolatedSelectedTextItems` | 容器、数字序号和文字 | 容器 `AXSelected` |

Apple 拼音、微信、搜狗和豆包保留显式 reader。它们的高亮或几何语义无法由当前
通用 Profile 完整表达，但这些差异限定在 reader 内，`MonitoringController` 和
HUD 不包含厂商分支。微信、搜狗和豆包在显式 reader 失效后统一回退到通用
reader 和 Profile 重验证。新输入法只要暴露上述通用结构，就无需新增专用代码。
显式 reader 明确报告候选已结束时不再执行通用二次扫描；只有结构失配、不可用等
可恢复状态才进入 fallback，避免无候选轮询重复消耗 AX 调用。

## 安全边界

- 不扫描普通宿主 App 的 `AXList`，避免误读侧栏、任务列表或其他文本。
- 只检查当前 TIS 输入源对应的输入法进程，不遍历其他 App。
- 不监听键盘、不截图、不执行 OCR、不调用输入法私有接口。
- Profile 和日志不包含候选原文；失败结果、错误和冷却时间不落盘。
- 只读取候选文字、frame、角色和选中语义，不读取输入框正文或真实文字选区。
- 密码框、Secure Input 和真实文字选区在候选读取前跳过。

## 探测与持久化

1. 未知输入法先使用标准 reader 读取宿主 App。
2. 组合输入或实际候选证据存在时允许后台探测；没有候选窗口时不扫描。
3. 当前组合只采样；成功 Profile 在下一次非组合边界启用，避免在半途改变链路。
4. 探测按单行列表、直接文字、分组文本项的顺序读取；分类时优先精确高亮结构，
   再使用无高亮列表降级。全局同一时间只运行一个探测任务。
5. Profile 身份由 Bundle 和输入源 ID 决定。输入法版本变化后，旧 Profile 只作为
   临时回退；首次候选读取必须安排一次受控重验证，不能把旧 Profile 直接标记为
   新版本已验证。
6. 持久化内容只有 Profile 身份、最近验证版本和结构枚举，不保存候选文本或当前窗口节点。
7. 已缓存 Profile 连续结构失配 3 次且持续 2 秒才失效；瞬时空值不会删除。
8. 探测失败按 `500ms / 2s / 10s / 30s / 1min / 5min / 10min` 渐进退避。
9. Profile 缓存键升级为 `candidateProfiles.v2`。旧 v1 是可重建的开发期缓存，
   不保存用户设置或候选文本，因此直接忽略。
10. 未知输入法首次使用可能暂时没有译文，这是明确的 best-effort 边界。

输入法只更新版本时，用户不应丢失翻译。旧 Profile 可临时读取，但首次候选读取会
在后台安排一次新版本验证；即使旧 Profile 暂时读取成功，也不能取消这次验证。
后台探测失败时保留旧 Profile 并进入退避，成功后替换 Profile。探测与交互读取通过
输入源级读取租约串行执行。

同一版本内若专用或 Profile Reader 返回结构失配，即使标准候选路径成功，也允许
重新探测，避免同版本灰度结构变化导致当前进程永久失效。探测提交带每个输入源的
单调 generation；输入法切换、成功读取或 Profile 失效后，旧探测结果必须丢弃。

同一输入源的 Profile 读取、探测读取通过输入源级读取租约串行执行，不同输入源
互不阻塞。Profile 内存状态、持久化和 generation 在同一串行边界内提交。

分组文本项 reader 按 Bundle 和输入源隔离缓存，最多保留 32 个 reader。热路径
验证进程会话、窗口归属、容器父链、子节点数量和原候选项身份；候选节点被重建或
窗口变化时重新发现。frame、`AXSelected` 和候选文字每轮重新读取。

## AX 资源上限

| 路径 | 上限 |
| --- | --- |
| 常规独立进程 reader | 3 个窗口 |
| 搜狗形态 | 24 个直接节点 |
| 微信形态 | 36 个直接节点 |
| 分组文本项 | 24 个容器或候选项节点 |
| 后台探测 | 2 个窗口、16 个节点、单次消息 `50ms` |
| 交互读取 | 192 次属性调用、总计 `300ms` |
| 后台探测 | 每个结构 64 次调用、总计 `150ms` |

候选运行态统一接受单行 `1...9` 项，运行中数量可变化。首次自动探测至少要求
2 个候选，用于避免把普通文本误判为候选栏。分组文本项还必须存在唯一容器
`AXSelected=true`。

这些限制不能中断已经发出的同步 AX 请求，但会约束后续调用和总节点数。

## 候选运行规则

- 候选变化时恢复 `40ms` 轮询；候选达到停留条件并启动翻译后降至 `80ms`。
- 候选停留默认 `100ms`，用户可调范围 `50–300ms`；已有用户保存的阈值保持不变。
- 翻译栏与原生候选栏的默认间距为 `6pt`，用户可调范围 `0–24pt`；已有用户保存的
  间距保持不变。
- 候选再次变化时立即恢复快速轮询，不增加翻译完成后的固定等待。
- 标准候选缓存验证窗口归属和候选列表身份；分组文本项缓存额外验证父链、子节点
  数量和候选项身份。
- Apple 拼音读取失败时可按宿主 PID 请求一次增强 AX；写入后必须回读确认。

## 故障行为

- 输入法缺失、窗口消失、确定性多行布局或结构错误时立即结束候选会话。
- 组合结束、失焦、真实文字选区、切换输入源时立即结束候选 HUD。
- AX timeout、瞬时空值等不确定失败使用两帧去抖，避免 HUD 闪烁。
- 已缓存 Profile 读取失败时回退标准 reader，不因此停止监控。
- 多行展开立即隐藏 HUD，但临时布局不计入结构失配，也不删除 Profile。
- TIS 缺少 Bundle ID 时不进行跨输入法探测，只保留标准候选路径。
- 候选读取失败不启动翻译模型，运行时仅静默隐藏 HUD。

## 验证工具

`CandidateProfileProbe` 用于验证指定输入法匹配的结构 Profile；
`SelectedTextItemCacheProbe` 用于验证分组文本项冷热读取和缓存命中。两者均只输出
结构、数量、耗时和缓存统计，不输出候选原文。
