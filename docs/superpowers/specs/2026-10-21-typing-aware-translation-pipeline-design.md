# Typing-Aware Translation Pipeline Design

- 日期：2026-10-21
- 状态：已实现，待真实拼音输入验收
- 范围：候选触发、OCR 连续帧确认、翻译调度、内存缓存、HUD 显示门槛

## 1. 目标

将现有“翻译完成后固定等待一段时间再显示”的机制，替换为“候选停留触发”：

1. 用户连续快速输入时不显示 HUD，也不启动大模型。
2. 用户停止输入后，尽可能快地显示一次有效翻译。
3. 候选变化后，旧结果不得延迟出现或覆盖新候选。
4. 对重复候选使用内存缓存，降低停顿后的首次响应时间。
5. 通过连续候选采样过滤瞬时 OCR 错误，不降低正常识别准确率。

最终用户不应感知“显示延迟”这一实现细节。系统表现为：打字时不打扰，停下来立即给出结果。

## 2. 非目标

- 不读取输入框正文或光标前上下文。
- 不读取选中文字内容；选区非空且不属于输入法组合范围时直接跳过。
- 不监听键盘事件。
- 不持久化候选文本、翻译结果或输入历史。
- 不引入新的内置词典。
- 不在本阶段实现跨请求 MLX KV 前缀缓存。
- 不改变词典优先和模型优先的既有路由顺序。
- 不为快速输入中的每个候选都启动模型推理。

## 3. 现有问题

当前 `MonitoringController` 在每轮候选中同步等待 `SmartRouter`，随后
`AppDelegate` 再等待用户配置的显示延迟。这个结构有三个问题：

- 翻译期间 OCR 循环被阻塞，无法及时观察新候选。
- 固定延迟发生在翻译计算之后，无法减少快速输入时的 OCR 和模型调用。
- 延迟时长不包含候选稳定性证据，既可能过长，也不能从原理上保证不闪烁。

## 4. 核心概念

### 4.1 Candidate Revision

每次检测到候选身份发生变化时递增的内部版本号。

候选身份由以下内容确定：

- 规范化后的 OCR 文本；
- 高亮区域的中心点和尺寸，使用小范围容差；
- 当前输入源、安全和权限状态。

候选 revision 必须随每个候选样本、翻译任务和显示请求传递。除当前 revision
以外的结果一律丢弃。

截屏前必须先通过焦点扫描门控：

- `AXTextInputMarkedRange` 明确为组合状态时允许扫描；
- 明确为非组合状态或无法读取组合范围时，焦点元素必须是可编辑文本控件，
  或可读取真实文本光标；
- 两者都不成立时不扫描。

该门控用于阻止点击菜单、聊天消息或普通按钮时，把窗口中的蓝色徽章误识别为输入法候选。

### 4.2 Candidate Dwell

“停留”不是单纯计时，而是以下条件同时成立：

- 至少获得两个连续有效采样；
- 连续采样对应同一候选；
- 高亮区域位置和尺寸在容差范围内；
- 最后一次候选变化后经过的时长达到用户配置的触发阈值。

只有停留候选才允许启动大模型或显示 HUD。

### 4.3 Trigger Delay

`DisplayPreferences.candidateDwellDuration` 使用新持久化键
`display.candidateDwellDuration`，语义为“候选停留多久后触发翻译和显示准备”。
项目尚未上线，因此不保留旧键兼容读取。

- 新安装默认值：120ms。
- 有效范围：80...300ms。
- UI 文案从“显示延迟”改为“候选停留”。
- 内部不再在翻译完成后追加固定等待。

## 5. 组件

### 5.1 `TypingActivityTracker`

纯 Swift 值类型，不依赖 AppKit、截图或模型。输入候选样本和单调时钟时间，
输出候选状态：

- `observing`：已有候选，但尚未形成停留证据；
- `dwelling`：当前候选满足停留条件；
- `changed`：候选 revision 已变化；
- `inactive`：没有候选、输入源不适用或安全输入已启用。

职责：

- 计算候选身份和 revision；
- 维护连续采样计数；
- 判断高亮几何是否稳定；
- 判断触发阈值是否达到；
- 不执行 OCR、翻译或 UI 操作。

必须使用可注入时钟或显式时间戳，保证单元测试稳定。

### 5.2 `TranslationCoordinator`

位于 `GlintMac` 的 actor，负责当前 revision 的翻译生命周期：

- 对停留候选调用 `SmartRouter`；
- 同一 revision 同时最多一个翻译任务；
- revision 变化时取消旧任务；
- 对不可立即中断的底层推理，至少保证旧结果不进入显示层；
- 将成功结果写入缓存；
- 只向 App 层发送仍然匹配当前 revision 的结果。

`MonitoringController` 继续负责截图、OCR 和输入源检查，但不再同步等待翻译完成。

### 5.3 `TranslationMemo`

仅驻留内存的精确结果缓存，键包含：

- NFC 规范化并去除首尾空白的候选文本；
- 源语言 `zh-Hans`；
- 目标语言 `en`；
- 词典优先或模型优先模式；
- 当前翻译模型选择 ID；
- 模型插件版本或 OpenAI provider 配置标识；
- prompt profile 版本；
- 已安装词典插件版本摘要。

规则：

- 只缓存成功且通过结果质量校验的完整 `TranslationResult`；
- 不缓存空结果、失败结果或部分输出；
- 不接受模糊候选匹配；
- 默认容量 512 条，建议总内存上限 4MB；
- 仅使用 LRU 淘汰，不写磁盘；
- 模型、prompt、词典版本或路由模式变化后，旧键自然失效；
- 相同 revision 的并发查询合并为一个任务。

### 5.4 `DisplayGate`

HUD 显示条件必须同时满足：

- `MonitoringController` 当前仍为苹果拼音；
- 未进入安全输入；
- 不存在非空文字选区；
- 当前候选处于 `dwelling`；
- 结果 revision 等于当前 revision；
- 结果通过统一质量校验。

`AppDelegate.scheduleHUD` 不再执行固定 `Task.sleep`，只继续负责 HUD 定位、
取消旧展示和防止重复显示。

### 5.5 HUD Presentation

`HUDController` 长期复用同一个 `NSPanel` 和 `NSHostingView`。
SwiftUI 内容由持久 `HUDPresentationModel` 驱动，翻译更新不得重建内容根视图。

- 首次显示：80ms 淡入，并向候选栏方向移动 2pt。
- 继续输入隐藏：60ms 淡出，完成后才 `orderOut`。
- 可见状态下候选变化：旧文字先保持 80ms；快速结果直接原位交叉淡化。
- 候选变化超过 80ms 仍无结果：旧文字降为约 30% 透明度。
- 30% 淡化占位持续到新结果到达或候选会话结束，不清空为无文字 HUD。
- 可见状态下小幅位置变化：90ms ease-out 移动。
- 淡出期间收到新结果：递增动画代次，取消旧 `orderOut`，重新淡入并更新文字。
- Reduce Motion：取消位移和亮度渐变；80ms 后直接进入 30% 淡化占位。

## 6. 数据流

```text
Focus gate（组合状态或可编辑焦点）
  -> 截图 + OCR
  -> CandidateSample
  -> TypingActivityTracker
       -> observing: 仅继续观察
       -> changed: 隐藏 HUD、递增 revision、取消旧任务
       -> dwelling: 请求 TranslationCoordinator
  -> TranslationMemo
       -> hit: 返回缓存
       -> miss: SmartRouter -> 词典或翻译模型
  -> ResultQualityGate
  -> DisplayGate
  -> HUD 立即显示
```

候选变化时发出 `candidateChanged`，取消旧翻译并启动旧内容保持计时。
`candidateEnded` 只在组合会话结束时发出，不等待翻译任务取消完成。组合范围从
`composing` 明确变为 `inactive` 且该轮没有候选时，立即结束会话；如果 App
不提供组合范围，则继续使用连续两帧 OCR 缺失的兼容回退。

## 7. 快速输入策略

### 7.1 连续输入

当候选在触发阈值内持续变化时：

- 保持 HUD 外壳；旧译文先保持 80ms，快速结果直接替换；
- 超过 80ms 仍无结果时，将旧译文降到约 30% 不透明度；
- 30% 淡化占位保持到新结果到达或候选会话结束；
- 不创建新的模型任务；
- 允许执行低成本的 OCR 和必要的缓存/词典检查；
- 持续更新最近候选变化时间和输入节奏。

### 7.2 候选停留

当候选满足停留条件时：

- 先查精确缓存；
- 未命中时执行当前路由；
- 翻译完成时如果 revision 仍有效，立即显示；
- 如果翻译尚未完成，结果返回时不追加固定等待。

### 7.3 恢复输入

如果 HUD 已显示，用户继续输入并产生新候选：

- 隐藏应在检测到新候选的同一轮内完成；
- 旧翻译任务取消；
- 已开始但无法中断的模型任务只允许在后台结束，不产生 UI 事件。

## 8. OCR 与准确率

准确率保护分为三层：

### 8.1 连续帧确认

- 默认要求两个连续候选样本的文本一致后才允许显示。
- 文本不一致时，候选保持 `observing`，不启动最终显示。
- 如果连续多次不一致且置信度低，可触发一次备用 OCR。

### 8.2 词典约束回退

仅在以下情况下调用备用 OCR：

- 主 OCR 置信度接近当前阈值；
- 结果很短但不像有效中文词条；
- 连续帧文本不一致。

若两个 OCR 结果不同，优先选择能在词典中命中、置信度更高且长度合理的结果。
无法可靠选择时保持隐藏，不猜测显示。

### 8.3 结果质量校验

所有模型输出在显示前必须满足：

- 单行英文；
- 非空；
- 不含解释性标签或残留控制标记；
- 中文内容比例不超过现有清洗规则；
- 输出长度与输入长度相比没有异常膨胀。

校验失败时按现有路由规则回退，不向用户展示错误占位文本。

## 9. 设置

`DisplayPreferences` 使用属性名 `candidateDwellDuration` 和存储键
`display.candidateDwellDuration`：

- 文案改为“候选停留”；
- 说明改为“候选停留多久后触发翻译”；
- 默认值改为 120ms；
- 范围改为 80...300ms；
- HUD 显示前不再再次睡眠；
- 预览使用生产显示门槛，但无需等待真实 OCR 连续帧。

开发阶段不读取也不迁移旧键。

## 10. 隐私与安全

- 候选文本和翻译结果只存在于进程内存；
- 日志只记录阶段耗时、revision、命中类型和结果状态，不记录原文；
- 安全输入期间不读取候选、不查缓存、不显示 HUD；
- 缓存随 App 退出清空；
- OpenAI 兼容接口的路由行为不变，只有用户主动选择远程模型时发送当前候选。

## 11. 错误处理

- OCR 暂时失败：继续观察；连续失败达到上限后隐藏并保持当前状态。
- 词典失败：按现有规则回退模型。
- 模型失败：按现有规则回退词典。
- 翻译任务取消：不产生用户可见错误。
- revision 过期：静默丢弃结果。
- 缓存异常：当作 miss，不影响主流程。
- HUD 定位失败：保持隐藏，不弹出运行时错误。

## 12. 性能观测

使用 OSLog signposts 或等价脱敏指标记录：

- 截图开始到 OCR 完成；
- 首次候选检测到 revision 确定；
- 组合会话结束到 HUD 隐藏；
- 翻译任务开始到翻译完成；
- 候选停留确认到 HUD 可见；
- 缓存命中、词典命中、模型完成、回退；
- 被取消或过期丢弃的任务数量。

禁止把候选文本、翻译结果或用户输入写入性能日志。

## 13. 测试计划

### 13.1 单元测试

- 候选每 50ms 变化时始终不进入 `dwelling`。
- 候选连续两个采样一致且达到阈值后进入 `dwelling`。
- 高亮位置变化超出容差时视为新 revision。
- 新 revision 到达后旧结果不能显示。
- 同一 key 的并发请求只执行一次。
- 缓存 key 对模式、模型版本和 prompt 版本敏感。
- 新键默认值和范围夹取正确，旧键不会被读取。
- 同一 HUD 生命周期内只创建一个 `NSHostingView`。
- 淡出期间的新结果不会触发重复 `orderFront`/`orderOut`。
- Reduce Motion 下不存在位移和文字交叉淡化。

### 13.2 集成测试

- 快速输入两秒：模型调用为零，HUD 不闪。
- 快速输入后停顿：只执行一次有效翻译并显示。
- HUD 显示后继续输入：同一轮检测内隐藏。
- 慢模型运行期间候选变化：HUD 外壳保持，旧结果不得恢复为正常不透明度。
- 缓存命中：停留确认后立即显示。
- 词典命中、词典失败回退模型、模型失败回退词典均保持原行为。

### 13.3 Release 性能验收

- 缓存或词典命中：从候选停留条件成立到 HUD 可见 p95 小于 120ms。
- Hy-MT2：从候选停留条件成立到 HUD 可见 p95 小于 250ms。
- OPUS-MT：从候选停留条件成立到 HUD 可见 p95 小于 180ms。
- 快速输入时，模型启动次数相对当前实现下降至少 80%。
- 旧 revision 结果进入 HUD 的次数必须为零。
- 空闲 CPU 不高于当前基线；OCR 连续采样不能造成持续高占用。

## 14. 实施顺序

1. 增加纯逻辑状态机、revision 模型和脱敏性能指标。
2. 将 OCR 观察与翻译任务解耦。
3. 将固定 HUD 延迟替换为候选停留触发。
4. 加入精确翻译内存缓存和并发请求合并。
5. 加入连续帧 OCR 确认和低置信度备用识别。
6. 使用 Release 构建完成快速输入、回退、缓存和真实 App 性能验证。

MLX 跨请求 KV 前缀缓存不进入本次实现，只在上线后由性能数据决定是否单独立项。

## 15. 完成标准

- 快速输入期间不再持续触发翻译和 HUD 闪烁。
- 用户停止输入后，HUD 由停留证据触发，而不是翻译完成后的固定延迟。
- 候选变化期间 HUD 不关闭，旧译文只作为淡化占位；组合结束后整体隐藏。
- 缓存命中路径明显快于模型首次推理。
- 准确率不低于当前词典回归和 OCR 基准，且瞬时 OCR 错误不会直接进入模型。
- 全部相关 Swift Package 测试和 Release 端到端验证通过。
