# 多语种翻译扩展设计

- 状态：已确认，待实现
- 日期：2026-11-03
- 范围：中文简体候选到英语或日语翻译；第一版只支持英语、日语两个目标语言
- 目标分支：`codex/multilingual-expansion-research`

## 1. 结论

Glint 增加全局“学习语言”概念。任意时刻只启用一个目标语言，源语言仍固定为
简体中文。目标语言决定翻译模型、词典路由、HUD 词性、朗读语音和翻译缓存隔离。

界面新增一级页面“语言与翻译”，负责当前语言下的翻译方式、当前模型、语言包和
语言语音。“插件与模型”只负责安装、更新、卸载和发现资源，不再承担当前翻译配置。

英语保留现有词典、词性、英语口音和三种翻译模式。日语第一版只使用模型，不接入
词典，不显示英文词性、英语口音或无效的翻译模式。

语言切换是低频长期偏好。选择新语言后立即成为当前学习语言；如果语言包或模型尚未
就绪，翻译显示暂停并展示页面内准备状态。准备成功后，如果切换前翻译显示处于开启
状态，则自动恢复，不要求用户再次启动。

## 2. 目标

1. 让用户在英语和日语之间进行清晰、全局、单选的长期切换。
2. 将语言配置集中在“语言与翻译”，让“插件与模型”保持资源管理职责。
3. 让模型、词典和 UI 通过显式能力描述支持的目标语言，不依赖模型名称或零散条件判断。
4. 保持英语现有行为、质量和交互不回退。
5. 日语第一版可只依赖 Apple Translation 或已验证支持日语的 MLX 模型工作。
6. 语言切换不能混用旧语言任务、缓存、朗读或 HUD 状态。
7. 为未来增加其他目标语言或日语词典能力保留清晰扩展点，同时不提前引入通用 Locale
   或语言档案系统。
8. 用必要重构消除“当前模型由推理运行时直接读取全局偏好”这一类职责耦合，避免多语言
   支持进一步放大技术债。

## 3. 非目标

- 不支持日语或其他语言作为候选源语言；Glint 仍只处理中文输入法候选。
- 不支持英语和日语同时显示。
- 不提供菜单栏快速目标语言切换。
- 不支持任意 BCP-47 目标语言列表；第一版只有封闭的英语、日语枚举。
- 不重新设计 HUD 视觉、定位、动画、插入或快捷键机制。
- 不增加生词本、学习统计、账号、云同步或翻译历史。
- 不允许用户添加远程翻译接口。
- 第一版不为日语接入 CC-CEDICT、ECDICT 或新的中日词典数据。
- 不把日语词性翻译成英文词性缩写，也不猜测日语词性。

## 4. 用户可见行为

### 4.1 当前学习语言

- 默认目标语言为英语。
- 已有用户升级后保持英语和原有英语模型选择。
- 全局只有一个当前目标语言。
- “语言与翻译”页使用“英语 / 日语”二选一分段控件。
- 目标语言变化会停止当前朗读、取消进行中的翻译、隐藏旧 HUD、清空翻译缓存，并准备
  新语言的翻译能力。
- 语言切换不会卸载任何模型或词典，不会删除其他语言上次使用的模型选择。
- 菜单栏只保留“显示主界面”“开启/关闭翻译显示”“检查更新”“退出”，不增加语言菜单。

### 4.2 导航与页面职责

侧栏顺序调整为：

```text
概览
通用配置
输入法支持
语言与翻译
显示与触发
插件与模型
权限与隐私
关于
```

职责如下：

| 页面 | 责任 |
| --- | --- |
| 概览 | 展示当前运行状态、目标语言、策略、翻译模型和能力摘要 |
| 通用配置 | 释义插入、朗读快捷键、朗读语速、自动朗读、开机启动 |
| 输入法支持 | 候选来源读取与安装 |
| 语言与翻译 | 目标语言、翻译方式、当前模型、语言包、语言语音 |
| 显示与触发 | HUD 范围、位置、外观、触发和当前语言下有效的显示能力 |
| 插件与模型 | 词典和模型的安装、更新、卸载与发现 |
| 权限与隐私 | 权限和隐私边界 |

“插件与模型”页不提供当前模型切换动作。已安装模型仍可检查更新、卸载或前往
“语言与翻译”选择；卸载当前模型前必须先切换模型。

### 4.3 “语言与翻译”页面

页面按以下顺序展示：

1. 学习语言：英语/日语选择，以及“中文 → 当前目标语言”的方向摘要。
2. 翻译方式：
   - 英语显示“智能融合 / 词典优先 / 模型优先”。
   - 日语显示“模型翻译”说明，不显示无法生效的三种模式。
3. 当前翻译模型：
   - 显示模型名称、方向、来源和当前状态。
   - 仅列出支持当前目标语言的已安装模型，并提供进入“插件与模型”的管理入口。
   - Apple Translation 的语言包安装状态和动作内嵌在此卡片。
4. 朗读语音：
   - 英语显示系统默认、美式和英式口音选择。
   - 日语显示系统日语语音，不显示英语口音选择。

日语缺少语言包或模型时，页面内显示准备状态和明确动作，不使用运行期弹窗、Toast
或常驻错误卡片。

### 4.4 概览状态流

概览状态流固定为：

```text
输入 → 语言 → 策略 → 翻译
```

- “语言”单元显示当前目标语言，是本状态流中唯一可点击进入“语言与翻译”的单元。
- 英语策略显示当前 `TranslationMode`。
- 日语策略显示“模型翻译”。
- “翻译”单元显示当前模型名称。
- “当前候选识别”属于内部实现，不再占据一级状态位。
- “翻译能力”摘要显示学习语言、翻译方式和翻译模型。
- Apple 语言包准备卡片按当前目标语言生成“中文到英语”或“中文到日语”文案。

### 4.5 语言切换状态

用户选择新语言时遵循“立即进入新语言，标记待准备”：

1. 立即持久化新目标语言。
2. 记录切换前翻译显示是否开启。
3. 停止朗读，取消当前翻译和自动朗读任务，隐藏 HUD，清空翻译缓存。
4. 解析该语言上次可用模型；不可用时退回 Apple Translation。
5. 准备模型和系统语言包。
6. 准备成功后更新翻译配置 token；如果切换前翻译显示开启，则自动恢复。
7. 用户取消语言包安装时，继续保留新目标语言和待准备状态。
8. 用户主动关闭翻译显示时，准备完成也不得自动恢复。

准备失败时不得回退到旧语言。界面保留新目标语言，并展示可操作的错误、模型选择或
语言包安装入口。

连续快速切换使用递增事务代次。旧代次完成、取消或失败时不得覆盖最新目标语言、
不得恢复旧模型，也不得重启 HUD。

### 4.6 英语状态

- 保留三种翻译模式、英文词典、词性、英语口音和现有 HUD 行为。
- 现有英语模型选择迁移为英语槽位。
- 切回英语时恢复英语最后一次可用模型；模型不可用时退回 Apple Translation。
- 词典优先、智能融合和模型优先的现有语义不变。

### 4.7 日语状态

- 第一版仅使用模型翻译。
- 不执行任何词典查询，不回退到英文词典。
- 不显示词性，不执行 `PartOfSpeechProviding`。
- 不显示“释义数量”；模型结果为单条译文。
- 使用系统日语语音；缺少日语语音时静默不朗读，不回退英语音色。
- 语言包使用 Apple `zh-Hans → ja`。
- 只允许当前选择兼容且声明支持日语的模型。
- 一栏模式的“候选翻译数量”仍有效，因为它限制参与翻译的候选数量，而不是单条
  候选的释义数量。

### 4.8 插件与模型页

- 继续显示“翻译词典 / 翻译模型 / 模型市场”。
- 页面顶部显示只读的“当前语言：英语/日语”。
- 每个翻译模型显示目标语言能力标签，例如“英语”“日语”“英语 / 日语”“仅英语”。
- 与当前语言不兼容的模型仍可见，以便管理安装和更新，但不可成为当前模型。
- 英文词典在日语状态下仍可见，并标记“仅英语参与路由”。
- 模型市场可以展示所有模型；安装确认和安装完成后必须显示目标语言能力与验证状态。
- 安装新模型不得自动成为当前模型；升级当前模型时只在原目标语言下重新验证和加载，
  不改变用户选择。
- 本地导入 MLX 模型只有通过目标语言专用探针后才能声明支持该语言；不得根据模型名称
  猜测。

### 4.9 通用配置与显示与触发

- “通用配置”移除翻译优先来源和英语口音；保留插入、朗读快捷键、语速、自动朗读和
  开机启动。
- 英语口音迁入“语言与翻译”，逻辑和数据键保持不变。
- “显示与触发”中“显示词性”只在英语状态出现。
- 日语选中模式隐藏“释义数量”；切换为一栏模式后继续显示“候选翻译数量”。
- 范围说明中的“英文翻译”统一改为“当前目标语言译文”或等价中性文案。
- HUD 预览根据当前目标语言切为英文或日文样例。
- 日语不显示任何词性占位或英文语音选项。

### 4.10 文案与无障碍

- 产品通用文案使用“译文”“当前目标语言”或具体语言名，不再默认只写“英文翻译”。
- 仅英文能力明确使用“英文词性”“英语口音”等措辞。
- 目标语言分段控件、模型能力标签和语言包状态必须提供完整无障碍标签。
- 日语样例在 VoiceOver 中按日语文本朗读，不逐字读出标签。

## 5. 领域模型

### 5.1 目标语言与方向

`GlintCore` 新增封闭枚举：

```swift
public enum TranslationTarget:
    String, CaseIterable, Codable, Sendable, Equatable, Hashable
{
    case english = "en"
    case japanese = "ja"
}
```

方向使用值类型表示，源语言固定但不以散落的 `"zh-Hans"` 字符串传递：

```swift
public struct TranslationDirection:
    Codable, Sendable, Equatable, Hashable
{
    public let source: TranslationSourceLanguage
    public let target: TranslationTarget
}
```

```swift
public enum TranslationSourceLanguage:
    String, Codable, Sendable, Equatable, Hashable
{
    case simplifiedChinese = "zh-Hans"
}
```

Apple 平台适配层负责把领域值映射为 `Locale.Language`；SwiftUI、持久化键和模型请求
不各自维护平台 Locale 字符串。

### 5.2 翻译请求

翻译接口改为接收包含方向的请求：

```swift
public struct TranslationRequest: Sendable, Equatable {
    public let candidate: Candidate
    public let direction: TranslationDirection
}

public protocol TranslationEngine: Sendable {
    func supports(_ direction: TranslationDirection) async -> Bool
    func translate(
        _ request: TranslationRequest
    ) async throws -> TranslationResult?
}
```

模型运行时和系统翻译都通过同一个请求显式获得方向，不再读取全局偏好推断目标语言。

### 5.3 模型能力

插件 manifest 增加：

```swift
public let translationTargets: [TranslationTarget]
```

规则：

- 缺失该字段的旧翻译 manifest 解释为 `[.english]`，保持现有插件兼容。
- Apple Translation 由动态 `LanguageAvailability` 决定英语、日语能力。
- `mt-opus-zh-en`、Hy-MT2、Index-Translate 等仅验证过中英的模型声明英语。
- 通用模型只有经过目标语言探针和产品评测后才能声明日语。
- CTranslate2 固定方向的数据包必须由 manifest 和运行时同时校验方向。
- `ctranslate2-data` 仍只允许固定托管 ID；新增中日数据包时必须显式扩展允许列表、
  发布资产和兼容测试，不能放宽为任意用户方向。
- 模型能力来自 manifest 与验证结果，不根据 `modelID.hasPrefix` 推断。
- 现有 `TranslationPromptProfile.inferred` 可以继续根据模型家族推断输入协议和解码
  参数，但该推断不能用于声明目标语言能力。

### 5.4 词典请求与路由

词典引擎和路由接收方向：

```swift
public protocol DictionaryEngine: Sendable {
    func lookup(
        _ request: TranslationRequest
    ) async throws -> TranslationResult?
}
```

`DictionaryRoute` 声明支持的方向集合。当前 CC-CEDICT、ECDICT 和通用中英 SQLite
词典只声明中英方向。`DictionaryRouter` 在进行任何查询前过滤不支持当前方向的路由。

日语第一版不创建日语词典路由，也不把英文词典结果当作日语回退。

### 5.5 路由

`SmartRouter` 每次路由都携带 `TranslationDirection`：

```swift
public func route(
    _ request: TranslationRequest,
    mode: TranslationMode,
    includesAlternatives: Bool,
    dictionaryPrefetch: Task<TranslationResult?, Never>?
) async throws -> TranslationResult?
```

- 英语保持现有三种模式。
- 日语只执行模型翻译；即使调用方传入其他模式，也不查询词典。
- 词性补全只在英语方向执行。
- 日语模型失败时返回无结果，不生成英文回退内容。

### 5.6 缓存

`TranslationMemoKey` 增加 `direction`。即使配置 token 生成错误，英语和日语也不能
命中同一缓存键。

翻译配置 token 至少包含：

```text
target
model ID
prompt schema version
all installed dictionary/model versions and hashes
```

语言切换时清空内存 LRU、候选预取结果和进行中的合并请求。切换事务完成后，新请求
使用新 token 和新方向。

## 6. 配置持久化与迁移

### 6.1 新键

```text
translation.targetLanguage      # en | ja，默认 en
translation.modelID.en          # 英语当前模型 ID
translation.modelID.ja          # 日语当前模型 ID
translation.multilingualMigration.v1
```

现有 `translation.modelID` 为已发布版本数据，需要迁移：

1. 先执行现有 OPUS 内置模型迁移。
2. 将迁移后的 `translation.modelID` 值复制到 `translation.modelID.en`。
3. 日语初始模型写入 `system-apple-translation`，但只在缺失时写入。
4. 当前目标语言初始化为英语。
5. 完成标记写入 `translation.multilingualMigration.v1`。

迁移必须幂等，重复执行不能覆盖用户之后选择的模型。

### 6.2 每语言模型记忆

- 英语和日语分别保存最后一次可用模型。
- 界面只显示当前目标语言的模型，不暴露“语言档案”概念。
- 切换时模型不兼容或未安装，退回 Apple Translation，并更新该语言槽位。
- 模型加载失败不自动选择另一个本地模型；保留失败状态并允许用户显式选择 Apple
  Translation 或其他兼容模型。
- 已安装但当前语言不兼容的模型不会因切换被卸载。

## 7. 运行时架构

### 7.1 职责调整

当前 `TranslationRuntime` 同时读取 `UserDefaults`、维护当前模型并执行推理。多语言支持
会放大这一职责耦合，因此实施时进行有针对性的重构：

```text
MainWindowModel / LanguagePage
  → TranslationLanguageCoordinator（App 组合根）
      → TranslationSelectionStore（GlintCore）
      → TranslationRuntime（GlintInference）
      → SystemTranslationCoordinator（GlintMac）
      → MonitoringSession
      → TranslationSpeechController
```

边界：

- `TranslationSelectionStore` 负责目标语言、每语言模型和旧数据迁移。
- `TranslationRuntime` 只负责解析、准备、释放和执行本地 MLX/CTranslate2 模型。
- `SystemTranslationCoordinator` 只负责 Apple 翻译会话、语言包和方向可用性。
- `TranslationLanguageCoordinator` 位于 App 层，串行化语言/模型切换事务，协调监控、
  HUD、朗读和两个翻译运行时。
- `MainWindowModel` 只发布可观察 UI 状态并调用协调器动作，不实现准备顺序。

### 7.2 本地模型运行时

`ResolvedTranslationModel` 增加方向能力：

```swift
public struct ResolvedTranslationModel: Sendable, Equatable {
    public enum Storage: Sendable, Equatable {
        case mlx(
            directory: URL,
            promptProfile: TranslationPromptProfile
        )
        case ctranslate2(directory: URL)
    }

    public let modelID: String
    public let storage: Storage
    public let supportedDirections: Set<TranslationDirection>
}
```

`TranslationRuntime` 接收显式配置并拒绝不支持的方向。`prepare`、`release` 和
`translate` 都不从全局偏好读取目标语言。

### 7.3 MLX 适配器

- Prompt profile 仍描述模型协议，目标语言作为独立维度传入。
- 单条和批量提示词按目标语言生成自然语言名称。
- 未知模型探针同时验证输出方向；英语探针不能作为日语兼容证据。
- 适配器缓存 schema 和缓存键包含目标语言。
- `warmUp` 使用当前目标语言的固定无隐私样例。
- 日语文字清洗不得使用“汉字比例过高即拒绝”的英语规则。

### 7.4 Apple Translation

- `SystemTranslationCoordinator` 从固定 `zh-Hans → en` 改为显式方向配置。
- 保留一个当前会话；方向变化时递增会话代次、取消旧请求并重建
  `TranslationSession.Configuration`。
- `LanguageAvailability` 查询使用当前方向。
- 切换目标语言后旧方向排队请求必须失败为取消或会话不可用，不能返回旧语言结果。
- 语言包下载仍只由用户动作触发；候选翻译阶段不触发下载。
- `SystemTranslationEngine.translate` 校验请求方向与当前会话方向一致。

### 7.5 语言切换事务

`TranslationLanguageCoordinator` 为每次切换分配递增代次，并串行执行：

1. 比较当前目标；相同则无操作。
2. 持久化新目标和切换前监控状态。
3. 停止朗读、取消自动朗读、取消翻译、隐藏 HUD、清空缓存。
4. 停止正在运行的监控会话，但不退出 App。
5. 解析目标语言的模型并检查方向能力。
6. 准备 Apple 语言包状态或本地模型。
7. 若代次不再是当前值，终止且不得产生 UI/监控副作用。
8. 更新当前配置 token、朗读语言和 UI 状态。
9. 若切换前监控开启且用户没有主动关闭，则重启监控。

语言包缺失、模型缺失或准备失败时停在“待准备/失败”状态，不执行步骤 9。用户安装
语言包或更换模型后再次走同一准备流程。

### 7.6 监控与 HUD

- 语言切换期间停止候选翻译触发并隐藏旧 HUD。
- 候选读取和 AX 会话不需要语言感知。
- 恢复监控前必须确认新翻译运行时已准备完成。
- HUD panel 和 hosting view 继续复用，不因语言切换重建内容根视图。
- 日语 HUD 不显示语言标签或词性，只显示纯日语译文。

### 7.7 输出校验

新增目标语言感知的纯领域校验，推理和展示共用同一组脚本边界规则：

- 英语继续拒绝明显中文回显。
- 日语允许汉字、平假名和片假名，不再按汉字比例拒绝。
- 两种语言共同拒绝多行结果、指令回显、模型控制标记、空结果和明显解释性长文本。
- 日语输出不得因为与中文候选共享汉字而被判定为回显；质量由日语评测集覆盖。

### 7.8 词性与朗读

- `PartOfSpeechProviding` 只接收英语目标和英文单词。
- 日语结果不查询 ECDICT 词性表。
- `TranslationSpeechController` 显式接收目标语言。
- 英语继续使用系统默认英语、美式或英式语音及 `en-US` 回退规则。
- 日语使用 `ja-JP` 或系统可用日语语音；缺失时静默跳过，不回退英语语音。
- 切换语言、停止监控或切换模型时立即停止当前朗读。

## 8. 状态与错误

UI 至少区分：

```text
preparing       正在准备当前语言的翻译
ready           当前模型和语言包可用
needsSetup      需要安装语言包或选择兼容模型
failed          准备失败，可重试或更换模型
unsupported     当前环境不支持目标方向，且没有可用本地模型
```

规则：

- 用户主动语言切换或模型选择可以显示页面内状态。
- 稳定运行后的普通推理失败继续静默隐藏译文。
- 权限错误继续使用现有权限流程；语言准备错误不弹窗。
- Apple 系统语言包下载窗口属于操作系统交互，允许显示。
- 模型准备失败不得切换到其他本地模型。
- `needsSetup` 和 `failed` 必须保留当前目标语言，不得回退英语。

## 9. 性能

- 语言切换是低频操作，可以承担一次模型释放和重新加载；不得在每次候选翻译时检查
  语言包或重新配置会话。
- 权限、语言包可用性和模型能力检查必须节流或缓存，不在候选轮询中重复访问系统 API。
- 英语翻译延迟和内存目标不得因方向参数增加明显回退。
- 日语模型只在当前目标语言下加载；切换语言前释放不再使用的多 GB 容器。
- HUD 宽度、高度和动画目标不因语言切换改变。
- 日语句子继续受现有单行和显示长度门控约束。

## 10. 重构要求

实施时允许并鼓励必要重构，但只重构与多语言职责直接相关的边界：

1. 把当前模型选择从 `TranslationRuntime` 移出，由选择存储和 App 协调器负责。
2. 用显式方向和能力集合替换固定 `zh-Hans → en`、`prompt=1` 和模型 ID 名称判断。
3. 将语言相关文案和条件控件集中到语言展示模型，不在 SwiftUI View 中重复写
   `if target == .japanese`。
4. 将目标语言输出校验集中为可测试的领域规则，避免 MLX 清洗和 HUD 过滤各自维护不同
   的汉字规则。
5. 将新页面拆成独立文件；不要继续扩张 `PluginsPage`、`GeneralPage` 或
   `MainWindowModel` 的视图和状态职责。
6. 不进行与多语言无关的 UI 重设计、路由重写、HUD 重构或模型运行时重写。

## 11. 测试

### 11.1 GlintCore

- 目标语言、方向编码和可用 Locale 映射。
- 英语和日语方向不相等，缓存键不碰撞。
- 旧模型偏好迁移一次且幂等。
- 旧翻译 manifest 缺少目标语言字段时只声明英语；新 manifest 能力原样保留。
- 英语模型不满足日语方向，多语模型满足两个方向。
- 英语三种模式行为不变；日语只走模型路由。
- 日语不调用词性提供者。
- 输出校验允许日语汉字/假名，英语继续拒绝中文回显。

### 11.2 GlintInference

- 英语提示词与当前输出保持一致。
- 日语单条和批量提示词明确要求日语，不出现英文输出要求。
- 日语模型结果允许汉字和假名。
- 未知适配器探针按目标语言分别缓存与验证。
- 不支持当前方向的本地模型被运行时拒绝。
- CTranslate2 固定方向模型不能接受错误目标语言。
- 切换模型后旧引擎和容器释放路径正确。

### 11.3 GlintMac

- Apple Translation 会话可在英语和日语方向之间重建。
- 切换方向后旧方向请求不会返回结果。
- 英语和日语语言包可用性独立查询和缓存。
- 日语输出通过 HUD 展示门控。
- 日语朗读请求 `ja-*` 语音，缺失时不回退英语。
- 运行中切换语言会取消旧翻译，并在准备完成后恢复监控。
- 快速连续切换只应用最后目标。

### 11.4 GlintUI

- 新侧栏项位于“输入法支持”和“显示与触发”之间。
- 英语状态显示三种模式、词性、英语口音和释义数量。
- 日语状态隐藏三种模式、词性、释义数量和英语口音。
- 插件页显示语言能力标签且不提供当前模型切换。
- 安装新模型不会改变当前模型；更新当前模型不会改变当前目标语言。
- 概览状态流为“输入 → 语言 → 策略 → 翻译”。
- 英语、日语 HUD 预览使用对应样例。
- 语言包未安装、安装中、失败和已安装状态文案正确。
- 浅色、深色、窗口缩放、VoiceOver 和 Reduce Motion 不回归。

### 11.5 真实 App 与 macOS 兼容

- 在 macOS 15 和 macOS 26 真实主机验证 `zh-Hans → ja` 支持与语言包安装。
- 验证英语语言包已安装时从英语切日语、从日语切英语的完整流程。
- 验证日语语言包未安装、下载中、取消、失败和完成后的自动恢复。
- 验证翻译显示原本关闭时，准备完成不得自动开启。
- 验证运行中切换语言、快速连续切换、切换模型时停止朗读和旧 HUD。
- 验证 Apple 拼音、微信、豆包、搜狗、Rime 的候选读取不因语言功能回归。
- 修改跨模块后执行完整 `./scripts/test.sh`。
- UI 完成时启动真实 App，检查浅色、深色、窗口缩放、空状态和日语样例。

### 11.6 日语质量

建立独立中日评测集，至少覆盖常用词、短语、短句、专名和歧义表达。发布前记录：

- Apple Translation 和每个声明支持日语的模型的 Top-1、缺失数、禁用输出命中数和 p95。
- 指令回显、英文误输出、多行输出和中文原样回显。
- 至少 120 条产品相关用例，其中 50 条为高频输入场景。
- 由中文母语且具备日语能力的人复核语义可接受度。
- 常用 50 条中不得存在明显语义错误；整体语义可接受率不低于 90%。
- 稳定推理 p95 不超过 200ms，超过时必须重新评估是否适合候选停留触发。
- 不只依赖精确字符串匹配；同义自然表达必须人工复核。

## 13. 架构决策摘要

- ADR-ML-001：目标语言是全局单选长期偏好，不提供同时翻译或菜单栏快速切换。
- ADR-ML-002：“语言与翻译”拥有当前配置，“插件与模型”拥有资源安装管理。
- ADR-ML-003：方向是显式请求值，不使用全局字符串或页面状态隐式推断。
- ADR-ML-004：模型和词典能力由声明的方向集合驱动，不按模型名称分支。
- ADR-ML-005：语言切换立即提交目标，能力未就绪时暂停翻译；不回退旧语言。
- ADR-ML-006：英语和日语分别记忆模型，但界面上只有一个当前目标语言。
- ADR-ML-007：日语第一版是模型-only，未来词典能力通过同一方向路由扩展。
- ADR-ML-008：语言切换由 App 层协调器串行化，UI 和推理运行时都不拥有切换流程。

## 14. 成功标准

1. 任意时刻只有一个当前学习语言，所有翻译、缓存、词性和朗读都使用该语言。
2. 英语现有行为、质量和 HUD 交互没有可感知回退。
3. 日语可以通过 Apple Translation 或已验证模型完成词、短语和短句翻译。
4. 日语不会出现英文词典回退、英文词性或英语语音。
5. 语言缺失或模型失败不会静默显示错误语言结果。
6. 语言切换不会混入旧 revision、旧缓存或旧朗读。
7. 新页面和运行时边界没有新增全局可变状态、模型名称分支或 UI 层跨模块编排。
8. 完整测试、真实 App 验证、macOS 15 兼容性验证和日语质量门禁通过。
