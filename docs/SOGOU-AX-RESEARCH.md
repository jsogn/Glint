# 搜狗拼音 AX 接入调研

- 日期：2026-10-23
- 系统：macOS 26.6.2（25G83）
- 搜狗拼音：6.25.3.12004
- Bundle：`com.sogou.inputmethod.sogou`
- 输入源：`com.sogou.inputmethod.sogou.pinyin`

## 结论

搜狗拼音和微信输入法一样，候选栏由输入法独立进程暴露，不在宿主 App 的
`InputMethodCandidateList` 中。候选文字和 frame 可读取，但当前公开 AX 没有
当前高亮候选项。

因此搜狗采用降级接入：

- 默认“选中”模式使用首候选，并标记 `selectionIsExact=false`；
- 用户主动选择“一栏”时，翻译当前单行全部可见候选；
- 一栏模式不把第一项伪造成选中项；
- 多行、展开或超过 9 个可见候选时隐藏；
- 不监听键盘，不截图，不调用搜狗私有接口。

## 实测结构

组合输入时，宿主 TextEdit 没有候选列表。`SogouInput` 进程出现一个独立窗口：

```text
AXWindow (AXUnknown)
└─ AXList (无 AXIdentifier)
   ├─ AXStaticText
   ├─ AXStaticText
   └─ ...
```

当前单行示例中，`AXList` 有 5 个可见静态文本节点。每个节点提供候选文字和
frame。候选序号由搜狗自行绘制，不是独立 AX 节点。

搜狗皮肤可能增加拼音区、边框和装饰高度。候选几何层分别声明横向和纵向来源：

- 横向锚点来自 `AXStaticText`，按文字节点规则补足候选单元左侧留白；
- 纵向边界优先使用 `AXWindow`，保留皮肤增加的拼音区和装饰区域，并固定内缩
  上下各 `8pt` 的默认皮肤透明边距；
- 窗口 frame 不可用时依次退回 `AXList` 和候选文字 frame。

默认皮肤以首次安装、默认 `8pt` HUD 间距为验收目标，不要求用户额外调整。不能
根据 AX 可靠识别当前皮肤，也不能区分其他皮肤内部仍存在的透明阴影或装饰留白。
因此第三方皮肤不单独适配；固定基线不匹配时，用户通过 HUD 间距调整。

如果 HUD 靠近屏幕边缘，固定选择“上方”或“下方”但该方向放不下时，布局会翻到
另一侧，而不是直接钳制坐标压缩间距。只有两侧都放不下时才使用屏幕边界钳制。

未发现：

- `InputMethodCandidateList`
- 非空 `AXSelectedChildren`
- 候选项 `AXSelected`
- 候选项 `AXFocused`
- `AXAttributedStringForRange` 参数化属性
- 选择变化时可用于读取高亮项的通知载荷

方向键会改变搜狗候选栏中橙色序号的视觉位置，但上述 AX 结构不变。候选居中、
左右定位和上下边界现在只依赖 `AXCandidateGeometry` 的节点来源，不需要
`MonitoringController` 增加搜狗专用判断。

## 搜狗桌面端差异

搜狗桌面端支持系统皮肤、自定义皮肤和不同候选布局，因此不能把微信的固定
前景色策略直接用于搜狗。颜色、背景、圆角和选中样式都可能随皮肤变化。

## 验收要求

- 默认仍由“显示与触发”的翻译范围控制，不强制切到一栏；
- 搜狗选中模式只显示首候选译文，不得声称已识别高亮；
- 搜狗一栏模式不得标记任一候选为当前选中；
- 宿主仍必须是可编辑文本输入，且不在安全输入或真实文字选区中；
- 搜狗升级后重新检查 `AXList` 和候选节点结构。

如果搜狗后续为当前候选项增加公开 `AXSelected`、`AXFocused` 或等价索引，
可直接把 `selectionIsExact` 升级为 true，并继续复用现有 reader。
