## 0. TL;DR

Glint 不替换输入法，而是在苹果拼音候选栏旁边加一层英文对照。

核心规则：

- 产品由一个**主窗口**和菜单栏 HUD 组成；主窗口负责模式、插件、权限和预览。
- 只处理**当前焦点候选**，不处理全部候选。
- 单词/短语只显示**最常用的一个英文对应词或短语**，不显示词性、释义、例句。
- 短句显示**自然的英文翻译**。
- 只显示**一行**，不发音、不收藏、不保存历史、不做复习系统。
- 默认“词典优先”：先查 schema-v2 词典，未命中或失败后交给当前本地翻译模型；另提供“模型优先”。
- 默认轻量翻译：OPUS-MT CTranslate2 int8（77MB）；专用 MLX 提供 Hy-MT2 1.8B 与 Index-Translate 2B，Qwen3 0.6B / 1.7B / 4B 保留用于多语言扩展。
- 词典和翻译模型统一为同一套**可下载插件体系**；第一版只提供官方预设，安装包不带模型。
- 歧义、低置信或没有可靠结果时**不显示 HUD**，运行时不弹窗。
- 8GB Apple Silicon 支持词典 + 轻量翻译模型；高质量模型建议 16GB。
- 第一版只支持 Apple Silicon，所有推理本地完成。

## 1. 背景与问题

中文母语者在日常输入中文时，经常遇到“我知道这个概念，但不确定英文怎么说”的瞬间。现有做法通常是：

- 切到词典 App 或网页查词；
- 选中文本后调用翻译工具；
- 复制到 AI 聊天窗口里问；
- 直接放弃，继续用中文表达。

这些动作都会打断输入，而且查到的内容往往是一大段释义，不是用户当下需要的那个英文词。

苹果拼音的候选栏本身就是用户注意力所在的位置。如果能在焦点候选旁边直接显示一行英文，用户不需要切换 App、不需要选中文本、不需要改变输入习惯，就能获得一次轻量的英文曝光。

## 2. 产品目标

### 2.1 目标

1. 在用户输入中文时，对焦点候选提供**即时、单行、可直接使用**的英文。
2. 保持苹果原生输入体验：不替换输入法、不改变候选排序、不抢焦点。
3. **默认全局生效**：任何 App 中使用苹果拼音都尝试显示，不依赖固定 App 列表；无法识别的 App 静默跳过。
4. 单词优先给英文对应词，短句给自然翻译；不把“英文释义”当成产品输出。
5. 支持离线词典和本地翻译模型两种能力，用户可自行下载、切换、删除。
6. 安装包保持轻量；模型按需下载；下载完成后推理完全离线。
7. 默认不保存输入内容、不监听键盘、不联网推理。
8. 按个人工具做：不做账号、付费、云同步、遥测和商业化支持。

### 2.2 非目标

- 不做自研输入法，不接入 InputMethodKit / librime。
- 不做生词本、复习、间隔重复、学习统计。
- 不做发音、TTS、音标。
- 不做英文释义、词性、例句、同义词树。
- 不做账号、云同步、社交、排行榜。
- 不做整段文档翻译或全文对照。
- 第一版不支持第三方输入法（搜狗、微信输入法、百度等）。
- 第一版不支持 Intel Mac。
- 第一版不以 Mac App Store 为主要分发渠道。
- MVP 不做应用白名单/黑名单；默认全局生效，过滤策略在后续版本再定。
- MVP 不在运行时弹窗；歧义、低置信、无结果、翻译失败都静默隐藏 HUD，只在主窗口/菜单栏显示状态。
- MVP 不开放任意第三方模型导入；只提供官方预设插件。

## 3. 目标用户

### 3.1 主要用户

- 中文母语者；
- 英语水平大约 B1–B2 或以上；
- 每天在 Mac 上大量输入中文；
- 使用苹果拼音「Pinyin – Simplified」；
- 希望在打字过程中被动接触英文表达，但不想切换工具或做额外学习任务。

### 3.2 典型场景

- 写工作消息时，想把“算法”“对齐”“复盘”换成英文表达；
- 写文档时，想确认某个中文短语的地道英文；
- 聊天时看到候选“你好吗”，想知道自然英文是 “How are you?”；
- 在任何使用苹果拼音的 App 中，都不想打断输入，也不想把内容复制到外部工具。

### 3.3 不服务的用户

- 主要使用第三方输入法的用户；
- 需要完整词典释义、例句、发音的用户；
- 需要系统化课程、复习计划、单词本的用户；
- 需要整段翻译或写作润色的用户。

## 4. 核心用户故事

1. 作为用户，我输入 `nihao`，焦点候选是“你好”，候选栏旁边显示 `hello`。
2. 作为用户，我输入一个短语候选“你好吗”，旁边显示 `How are you?`。
3. 作为用户，我输入一个成语或固定短语，词典命中时显示对应的英文短语。
4. 作为用户，输入先查词典；未命中词典时使用当前选择的本地翻译模型，单词、短语和句子都适用。
5. 作为用户，我可以下载、切换、删除词典插件和翻译模型插件。
6. 作为用户，我不希望它记录我输入过什么，也不希望它把我的文本发到网络。
7. 作为用户，当我在密码框或安全输入场景中，提示层完全不出现。

## 5. 产品原则

1. **原生优先**：不改变候选栏、不改变按键、不抢焦点。
2. **一次一行**：只显示当前焦点候选对应的英文，不展示释义列表。
3. **默认词典优先**：schema-v2 词典提供快速首选，模型负责未命中、句子和失败回退。
4. **本地优先**：候选读取、词典、模型推理都在本机完成。
5. **不猜**：没有可靠结果时显示“未收录”或提示安装插件，不编造。
6. **最小权限**：候选识别和上下文读取只需辅助功能；不使用屏幕录制、输入
   监控，不记录键盘。
7. **可插拔**：词典和翻译模型都是可下载、可替换的能力，不写死在 App 里。

## 6. 功能需求

### 6.1 焦点候选识别

- 仅在当前输入源为苹果拼音 `com.apple.inputmethod.SCIM.ITABC` 时工作。
- 默认全局生效，不依赖固定 App 列表；任何 App 中只要 TIS、辅助功能和候选栏可用，就尝试显示。
- 如果某个 App 不暴露光标/控件 frame，或候选栏无法识别，静默跳过，不弹错误、不阻塞输入。
- 如果 `AXSelectedTextRange` 非空且不属于 `AXTextInputMarkedRange`，说明存在文字选区，静默跳过、不翻译。
- 后续版本可以增加白名单/黑名单，但 MVP 固定为全局。
- 通过辅助功能获取焦点文本控件的光标位置和控件 frame。
- `AXTextInputMarkedRange` 处于组合状态时直接允许扫描。
- 组合状态为结束或无法读取时，焦点元素必须明确为可编辑文本控件，或提供真实文本光标，才读取候选。
- 菜单项、按钮、消息列表等不可编辑焦点元素直接跳过。
- 从宿主 App 的 AX 窗口树读取 `InputMethodCandidateList`。
- 当前焦点候选来自列表的 `AXSelectedChildren`，文本来自 `AXTitle`，位置来自 `AXFrame`。
- 候选列表不存在或没有选中项时静默隐藏，不启动后续流程。
- 只处理输入法候选；不读取文本控件正文。
- 候选变化、提交、失焦或切换输入法时，及时刷新或隐藏。
- 安全输入（密码框、终端安全输入等）直接跳过。
- 当前只保证苹果拼音默认强调色和常见深浅主题下的稳定性。

### 6.2 输出规则

- 默认“选中”：只显示当前焦点候选的一行英文。
- 可选“一栏”：按当前高亮候选所在行显示，保留序号并高亮焦点项。
- 多行候选必须按 `AXFrame` 分行，不能把所有可见候选压平成一行。
- “一栏”HUD 固定锚定整条候选栏；切换栏目内焦点时不得重新定位 HUD。
- 候选栏展开为网格或多行时，不显示一栏 HUD，避免在错误行或错误位置展示。
- “一栏”只读取 `AXSelectedChildren` 与 `AXVisibleChildren`；可见集合包含选中项
  且数量合理时直接作为首栏活动行，否则只显示当前选中项。全量 `AXChildren`
  不参与一栏候选构造；候选窗进入多行展开状态后立即隐藏翻译栏并停止处理。
- 一栏 HUD 为每个候选项保留不可压缩的最小槽位，禁止用省略号截断译文；完整
  行超过屏幕可用宽度时，退回只显示当前选中候选的完整译文。
- 一栏 HUD 的外层左右内边距保持 `3pt`，贴近候选栏边缘密度；选中胶囊内部
  保留 `5pt` 水平内边距，避免文字贴边。

#### 单词/短语

- 输出一行英文对应词或短语。
- 不输出词性、英文释义、例句、音标。
- 默认只给一个最常用对应词。
- 如果两个表达在词频和语义上几乎等价，可以用 `/` 连接，最多两个；仍保持一行。
- 示例：

```text
算法      → algorithm
计算      → calculate
复盘      → retrospective
你好      → hello
```

#### 短句

- 输出一行自然的英文翻译。
- 不做逐词直译，不解释语法。
- 示例：

```text
你好吗          → How are you?
今天天气不错    → The weather is nice today.
```

#### 无法处理

- 数字、emoji、纯符号、无法识别的候选：不显示面板。
- 歧义、低置信、词典未命中且没有可用翻译插件：不显示 HUD，不编造英文。
- 翻译失败：不显示 HUD；只在主窗口或菜单栏显示状态。
- 运行时不弹窗；系统权限提示除外。

### 6.3 模式与路由

用户可以在设置中选择两种模式：

| 模式 | 行为 |
|---|---|
| 词典优先（默认） | 先查 schema-v2 词典；未命中或词典失败 → 当前翻译模型 |
| 模型优先 | 当前模型结果第一；单词/短语追加词典候选；无结果或失败 → 查词典 |

路由规则：

1. 词典优先：先合并查询当前词典插件；命中后按保留义项和排序返回，不再让静态 Override 强制首位。
2. 模型优先：先请求当前翻译插件；成功后将模型候选放在首位。
3. 模型优先处理单词/短语时继续查询词典，并追加去重后的词典和低优先级策展候选；句子跳过额外词典查询。
4. 首选来源无结果或失败时回退另一来源，不因 CandidateKind 为 word/phrase 而跳过。
5. 没有安装任何插件或没有可靠结果时，HUD 不显示；主窗口/菜单栏显示插件状态，不弹窗。

词典命中不等于结果可信。候选是单字、词条有多个明显不同的英文对应词、或词典只能给出解释性长句时，继续按排序规则选择；两个模式的首选来源失败后都必须回退另一来源。

### 6.4 词典与翻译插件

#### 插件类型

- **词典插件**：提供中文词条 → 英文对应词/短语的快速查询。
- **翻译插件**：提供短句自然翻译，也可作为词典未命中的兜底。

#### 插件管理

- 插件列表显示：名称、类型、大小、质量等级、速度、最低内存、许可证、安装状态。
- 支持下载、校验、安装、切换、删除、更新。
- 下载完成后完全离线；推理不发起网络请求。
- 安装包不包含完整词典或模型，保持小体积。
- 首次启动提供引导，让用户选择并下载基础插件。
- 插件 manifest 和模型文件都要校验 SHA256。
- 词典和翻译模型统一为同一套插件体系：共用 manifest、PluginManager、安装目录和下载校验。
- 第一版只提供官方预设插件；用户可下载、切换、删除，不开放任意第三方模型导入。

#### 预设插件（候选）

| 插件 | 类型 | 体积量级 | 定位 |
|---|---|---|---|
| CC-CEDICT | 词典 | 十几 MB | 基础词典，默认安装 |
| **OPUS-MT CT2 int8** | 翻译 | **77MB** | **默认轻量翻译**；p50 18.7ms、p95 41.2ms、RSS 256MB |
| **Hy-MT2-1.8B 4-bit** | 专用翻译 | **1.02GB** | **高质量档**；p50 49ms、RSS 1.45GB |
| Index-Translate-2B 4-bit | 专用翻译 | 1.08GB | 质量备选；p50 53ms、RSS 1.63GB |
| Qwen3-0.6B 4-bit | 翻译/LLM | 351MB | 低内存档；p50 49.8ms、RSS 876MB |
| Qwen3-1.7B 4-bit | 翻译/LLM | 984MB | 通用多语言保留档；p50 141.5ms、RSS 1.47GB |
| Qwen3-4B 4-bit | 翻译/LLM | 2.28GB | 高质量档；p50 166.6ms、RSS 2.7GB |
| Apple Translation | 系统翻译 | 0 插件下载；系统语言包可能需下载 | 可选，取决于系统可用性 |

专用翻译模型与 Qwen 通用模型同时保留：前者作为纯中英翻译默认路径，后者用于后续多语言能力扩展。M2M100-418M 已被 M1 淘汰：p50 255ms、RSS 2.7GB、缓存 3.6GB，质量没有优势。

### 6.5 HUD 显示

- 单行显示，不换行。
- 自动宽度，按完整文本的自然宽度布局，禁止用省略号截断；完整行超过屏幕
  可用宽度时，只显示当前选中候选的完整译文。
- 位于候选栏下方；空间不足时翻到上方。
- 不覆盖候选栏本身，不抢焦点，不改变当前候选选择。
- HUD 使用持久面板和持久内容根视图；文字更新不得重建整个面板。
- 显示使用约 80ms 淡入，隐藏使用约 60ms 淡出；组合输入中候选位置和宽度变化
  立即贴合，不播放窗口 frame 动画，不使用弹跳或缩放。
- HUD 显示期间宽度只增不减，避免组合词汇增删时反复缩放；下一次独立显示时
  重新按当前内容计算宽度。
- 淡出期间出现新有效结果时，保持面板并原位交叉淡化，不得重复关闭再打开。
- 开启“减少动态效果”时取消位移和文字过渡。
- 连续快速输入时不启动大模型，也不显示 HUD。
- 同一候选连续采样一致并停留达到触发阈值后，才触发翻译；翻译完成即显示，不再追加固定等待。
- 候选停留默认 120ms，可调范围为 80–300ms。
- 候选内容变化时保留 HUD；上一条译文先保持 80ms，快速结果直接原位替换，超过 80ms 后才降为低透明度占位。
- 低透明度占位会持续到新结果到达或候选会话结束，不显示完全空白的 HUD。
- 候选栏结束、提交、失焦、切换输入法或安全输入时隐藏 HUD。
- 组合范围明确结束时立即关闭；两帧缺失去抖只保留在无活动候选会话的兼容路径。
- 开启“减少动态效果”时不执行亮度渐变；80ms 后直接切换到低透明度占位。
- 歧义、低置信、无结果或翻译失败时不显示；不弹窗。
- 默认无按钮；发音和收藏都不做。
- 支持浅色/深色外观；焦点识别不依赖固定高亮颜色。

### 6.6 主窗口

Glint 除了菜单栏 HUD，还需要一个完整的主窗口。它不是一次性的 Preferences 弹窗，而是用户打开 App 后看到的产品控制台。

窗口形态：

- 独立 `NSWindow`，左侧分组导航，右侧内容区；
- 参考 Bob/系统设置的分组侧栏，但不复制其视觉；
- 默认约 1120×720，最小约 960×640；侧栏 220–240pt；内容区可滚动；
- 透明标题栏、全尺寸内容、系统强调色、深色/浅色自适应；
- 关闭窗口只隐藏，不退出 App；后台监控继续。

侧栏结构：

| 分组 | 页面 | 内容 |
|---|---|---|
| 产品 | 概览 | 监控开关、当前状态、输入源、当前模式、插件/权限摘要 |
| 翻译 | 翻译设置 | 词典优先/模型优先策略 |
| 输入 | 显示与触发 | HUD 位置、候选停留、透明度、间距和实时预览 |
| 能力 | 插件与模型 | 词典插件 + 翻译模型；安装/更新/删除/切换、速度/质量/内存 |
| 安全 | 权限与隐私 | 辅助功能状态、隐私说明、日志 |
| 产品 | 关于 | 版本、更新、第三方许可证 |

页面要点：

- **概览**：顶部状态卡（翻译显示已开启/已关闭）、开启/暂停按钮、当前 App、当前输入源、当前模式、插件摘要、权限缺失提示。
- **翻译设置**：选择词典优先或模型优先；两个模式下首选来源失败都会回退到另一来源。
- **显示与触发**：HUD 位置（自动/上方/下方）、候选停留达到多久后触发、透明度和间距；用一个模拟候选栏 + HUD 做实时预览。
- **插件与模型**：上半部分是词典插件（当前版本、大小、安装/更新/删除、英文对应词策略）；下半部分是翻译模型（列表、默认插件、大小/速度/质量/最低内存/许可证、下载进度、删除、切换）。
- **权限与隐私**：辅助功能状态卡、打开系统设置、“不读取正文/不保存文本/不联网推理”的说明。
- **关于**：版本、更新、第三方许可证、项目链接。

第一版把词典和翻译模型合并为一个页面，避免侧栏过于稀疏；如果后续插件数量增加，再拆成两个独立页面。

布局草图：

```text
┌──────────────────┬────────────────────────────────┐
│ 概览              │ 插件与模型                       │
│ 显示与触发        │ ┌────────────────────────────┐ │
│ 插件与模型        │ │ 词典                        │ │
│ 权限与隐私        │ │ CC-CEDICT  [已安装] [更新]  │ │
│ 关于              │ └────────────────────────────┘ │
│                  │ ┌────────────────────────────┐ │
│                  │ │ 翻译模型                    │ │
│                  │ │ OPUS-MT   [使用] [删除]     │ │
│                  │ │ Qwen3-4B  [下载]            │ │
│                  │ └────────────────────────────┘ │
└──────────────────┴────────────────────────────────┘
```

窗口行为：

- 菜单栏提供“打开主窗口”；首次启动默认打开主窗口，而不是弹一个阻塞式欢迎框。
- 主窗口关闭后 App 继续驻留菜单栏，HUD 继续工作。
- 第一版只驻留菜单栏，不显示 Dock 图标。
- 通过 AppKit `NSWindow` + `NSHostingView` 承载 SwiftUI 内容；窗口生命周期由 AppKit 管，页面用 SwiftUI。
- 侧栏用 `NavigationSplitView` + `List(selection:)`；设置卡片用 `Form(.grouped)`/`Section`；不引入第三方 UI 组件库。
- 采用系统控件、SF Symbols、系统强调色和 `NSVisualEffectView`；视觉接近系统设置，而不是自造一套 UI 框架。

状态设计：

- 无插件：显示下载卡片和“下载后启用”按钮。
- 下载中：显示进度、暂停/取消、禁用删除。
- 权限缺失：主窗口顶部显示黄色提示条和“打开系统设置”。
- 模型超出内存：显示最低内存要求，禁用安装。
- 翻译失败：显示轻量错误状态，不把错误文本写进日志。

### 6.7 设置

设置是主窗口中的页面，不是独立的小弹窗。至少包含：

- 模式：词典优先 / 模型优先；
- 词典插件：当前使用、下载、更新、删除；
- 翻译插件：当前使用、下载、更新、删除；
- 模型存储位置和占用空间；
- 离线状态；
- HUD 位置：自动 / 上方 / 下方；
- 候选停留；
- 高亮颜色校准；
- 应用过滤（后续版本；MVP 不做白名单/黑名单）；
- 权限状态与重新授权入口；
- 隐私说明和日志开关；
- 关于与第三方许可证。

不包含：生词本、复习计划、发音、账号、同步。

### 6.8 权限与隐私

- 当前候选识别需要辅助功能：读取光标、控件 frame 和输入法候选。
- 只使用辅助功能读取候选和有界上下文，不截图、不执行 OCR。
- 不需要输入监控，不监听键盘。
- 不读取文本控件正文，只读取光标位置和控件 frame。
- 只读取选区与输入法组合范围以排除真实文字选区，不读取选中文字内容。
- 不保存候选文本、翻译结果或输入历史；仅允许内存 LRU 缓存。
- 不记录按键、不记录剪贴板、不记录窗口标题。
- 安全输入场景自动跳过。
- 模型下载是唯一允许的网络行为；推理阶段不联网。

## 7. 非功能需求

### 7.1 性能目标

| 指标 | 目标 |
|---|---|
| 词典查询 p95 | < 50ms |
| 候选停留触发到缓存/词典 HUD 出现 p95 | < 120ms |
| 候选停留触发到 Hy-MT2 HUD 出现 p95 | < 250ms |
| 候选停留触发到 OPUS-MT HUD 出现 p95 | < 180ms |
| 模型首 token | < 300ms |
| 短句翻译完成 | < 600ms（30 字以内） |
| 空闲 CPU | < 2% |
| 翻译时 CPU | < 10% |
| 词典模式内存 | < 150MB |
| 轻量翻译插件内存 | < 1.5GB |
| 高质量插件内存 | < 6GB |

内存分级：

- 8GB Apple Silicon：支持词典模式和轻量翻译模型；
- 16GB 及以上：可下载高质量翻译插件；
- 下载前检查可用内存，不满足时禁用安装并提示最低要求。

### 7.2 准确性目标

- 常用单词英文对应准确率：> 90%（人工评测集）。
- 短句自然度：人工 1–5 分评测，80% 以上样本 ≥ 4 分。
- 不允许出现明显中文、解释性长句或模型自我说明。

### 7.3 兼容性

全局策略：

- 默认全局生效，不依赖固定 App 列表；
- 任何 App 中使用苹果拼音都尝试显示；
- 无法识别的 App 静默跳过，不影响输入；
- MVP 不做白名单/黑名单；后续再定过滤策略。

验证目标（不是白名单）：

- macOS 14+；
- Apple Silicon；
- 苹果拼音「Pinyin – Simplified」；
- TextEdit、Safari、Chrome、VS Code、微信、Word；
- 系统强调色和浅色/深色主题；
- 单显示器；多显示器作为 best effort。

暂不支持：

- Intel Mac；
- 第三方输入法；
- 第三方输入法及其自定义皮肤；
- 候选栏位于光标上方且远离文本框的特殊布局；
- 全屏游戏、远程桌面、虚拟机等特殊渲染环境。

### 7.4 安全与分发

- Developer ID 签名 + 公证；
- 直接下载分发，暂不上 Mac App Store；
- 插件模型只作为数据加载，不执行任意第三方代码；
- 固定运行时适配器；
- 所有下载校验 SHA256；
- 第三方词典/模型许可证随插件展示；
- 更新使用 Sparkle 或等价的安全更新机制。

## 8. 技术方案概要

### 8.1 数据流

```text
苹果拼音候选栏
  → TIS 判断输入源
  → Accessibility 获取光标/文本框 frame
  → Accessibility 读取 InputMethodCandidateList / AXSelectedChildren / AXFrame
  → SmartRouter
  → DictionaryPlugin / TranslationPlugin
  → 单行 HUD
```

### 8.2 模块

- `InputContextMonitor`：TIS + AX 状态、光标位置、安全输入判断。
- `AXCandidateReader`：读取当前输入法候选和 frame。
- `SmartRouter`：根据模式、词典命中、候选类型选择插件。
- `DictionaryPlugin`：CC-CEDICT/扩展词典查询，返回最佳英文对应词。
- `TranslationPlugin`：本地翻译模型推理，返回自然英文。
- `PluginManager`：manifest 解析、下载、校验、安装、删除。
- `ModelManager`：模型文件、运行时、内存检查、版本更新。
- `HUDController`：单行非激活面板，定位与自动隐藏。
- `MainWindowController` / `MainWindowView`：AppKit 窗口外壳 + SwiftUI 侧栏/页面；从菜单栏打开，关闭后隐藏。
- `AppPolicy`：应用过滤策略；MVP 固定 `.all`，后续扩展为白名单/黑名单。
- `SettingsStore`：模式、插件、HUD、隐私设置。
- `Diagnostics`：隐私安全的日志、延迟指标、错误状态。

### 8.3 运行时

- 词典：SQLite + CC-CEDICT；可选 ECDICT 反查/词频排序。
- 专用翻译模型：OPUS-MT CTranslate2 int8；M2M100 不再作为默认预设。
- 通用 LLM：优先 MLX（Apple Silicon），llama.cpp 作为备选。
- Apple Translation：作为可选系统插件，不强行依赖。

### 8.4 线程与缓存

- 候选读取和翻译全部离开主线程。
- 主线程只负责 HUD 和设置 UI。
- 候选观察与翻译任务解耦，慢模型不得阻塞下一轮候选检测。
- 只有停留候选可以启动模型；快速输入期间模型调用应接近零。
- 候选变化时取消旧请求并保留 HUD 外壳；旧译文降为低透明度，无法立即中断的旧结果必须按 revision 丢弃。
- 只有组合会话结束时才隐藏 HUD。
- 精确翻译结果使用内存 LRU 缓存和并发请求合并；不落盘。
- 模型常驻内存；词典使用 mmap/SQLite 读取。

```text
~/Library/Application Support/Glint/
  plugins/
    dict-cedict/
      manifest.json
      dictionary.sqlite
    mt-opus-zh-en/
      manifest.json

  cache/
```

### 9.3 安全约束

- 不允许插件携带 dylib、脚本或可执行文件。
- 插件只能包含 manifest、模型权重、词库数据和固定格式的配置。
- 运行时由 App 内置的适配器提供。
- 下载必须校验大小、SHA256、版本和运行时兼容性。
- 删除插件时必须清理模型和缓存。

## 10. 成功指标

### 10.1 激活

- 首次启动完成基础插件下载的比例；
- 辅助功能权限授予率；
- 首次成功显示 HUD 的比例。

### 10.2 使用

- 日活用户数；
- 每人每日 HUD 展示次数；
- 每人每日主动切换模式/插件的次数；
- 关闭监控或卸载的比例。

### 10.3 质量

- 单词英文对应人工准确率；
- 短句自然度人工评分；
- “翻译错误/看不懂”反馈率；
- 模型输出中出现解释、中文、引号、长句的比例。

### 10.4 性能与信任

- HUD 出现 p95 延迟；
- 模型模式 p95 完成时间；
- CPU/内存占用；
- 打字速度影响（用户主观 + 小样本计时）；
- 崩溃率；
- 是否有任何文本被写入磁盘或发送到网络。

记忆强化本身很难用产品内指标直接衡量；MVP 不通过生词本或复习数据来证明价值。Beta 阶段可以做一次小样本回忆测试，但不作为首发阻塞项。

## 11. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 用户不信任辅助功能权限 | 激活率低 | 明确只读取候选和有界上下文，不读正文、不存文本、不截图 |
| 候选栏 AX 结构变化 | 识别失败 | 静默跳过；通过兼容性矩阵和版本化测试定位 |
| 全局生效后 App 兼容性差异大 | 某些 App 无 HUD | 静默跳过；提供兼容性诊断；后续白名单/黑名单 |
| 词典只能给释义，选不出唯一英文对应词 | 单词结果不准确 | 词频/ECDICT 反查/人工 override；复杂词走模型 |
| 小翻译模型质量不够 | 短句翻译生硬 | 默认轻量插件 + 高质量插件可选；模型 spike 选型 |
| 本地 LLM 内存/延迟过高 | 低配 Mac 不可用 | 模型按需下载；显示最低内存；默认轻量翻译模型 |
| 插件下载/许可证复杂 | 合规和分发风险 | 官方预设插件；逐项核对许可证；manifest 展示 |
| 多显示器/全屏定位 | HUD 位置错误 | MVP 单屏；多屏 best effort；后续校准 |
| Apple 修改候选栏或系统翻译 API | 兼容性回退 | 版本检测；静默跳过不支持控件；不依赖私有 API |
| 用户以为是输入法或全文翻译 | 预期错位 | 产品文案明确“焦点候选英文对照”，非翻译器/输入法 |

## 12. MVP 范围与验收

### 12.1 MVP 包含

- 苹果拼音焦点候选识别；
- 默认全局监控，不依赖固定 App 列表；MVP 不做白名单/黑名单；
- 单词/短语 → 一行英文对应词；
- 短句 → 一行自然英文翻译；
- 歧义/低置信/无结果时不显示 HUD，运行时不弹窗；
- 词典优先 + 模型优先；
- CC-CEDICT 词典插件；
- 至少一个轻量本地翻译插件；
- 词典与翻译模型统一插件体系；v1 仅官方预设，支持下载/切换/删除；
- 带左侧分组导航的主窗口（概览/显示/插件与模型/权限/关于）；
- 8GB Apple Silicon 支持词典 + 轻量翻译模型；
- 单行 HUD；
- 辅助功能引导；
- 安全输入跳过；
- 本地推理、无文本持久化；
- Developer ID 签名和公证。

### 12.2 验收标准

1. 默认全局监控；在 TextEdit、Safari、Chrome、VS Code、微信、Word 等代表性 App 中，苹果拼音候选出现时能显示 HUD，不需要手动添加 App 白名单。
2. 焦点候选为“你好”时显示 `hello`；为“你好吗”时显示 `How are you?`。
3. HUD 不抢焦点，不改变候选选择；提交后消失。
4. 词典模式 p95 < 100ms；模型模式 30 字以内 p95 < 600ms。
5. 安装包不含模型时 < 50MB。
6. 卸载/删除插件后，对应能力立即不可用，且不残留模型。
7. 在密码框/安全输入场景中不出现 HUD。
8. 日志中不出现候选文本、用户输入或翻译内容。
9. 主窗口可从菜单栏打开；关闭后 HUD 和监控继续工作；侧栏页面可正常切换。
10. 歧义、低置信或无可靠结果时不显示 HUD；运行时不弹窗。
11. 8GB Apple Silicon 可运行词典 + 轻量翻译模型；高质量模型在内存不足时禁用安装并提示 16GB。
12. 第一版只驻留菜单栏，不显示 Dock 图标。

### 12.3 MVP 不包含

- 生词本、复习、间隔重复、学习统计；
- 发音、音标、TTS；
- 英文释义、例句、词性；
- 第三方输入法；
- Intel Mac；
- 全文翻译；
- 账号、云同步；
- Mac App Store 首发。

## 14. 待讨论

1. 单词/短语是否允许两个同义表达用 `/` 连接？当前建议默认只给一个，极少数并列时最多两个。
2. 词典模式如何继续优化“最佳英文对应词”：ECDICT 反查 + 词频 + 人工 override，还是做更大的精编词表？
3. 多显示器/全屏是否作为 MVP 阻塞项？建议不作为阻塞项，但要做基本 best effort。
4. 模型下载的托管方式：自建 CDN、GitHub Releases，还是模型平台直链？
5. Apple Translation 是否作为“零下载”预设插件？需要验证 API 可用性和语言包。
6. 白名单/黑名单的产品形态与生效范围：全局默认，后续再定。
7. Qwen3-4B 的具体量化版本和插件下载体积，需要在 M2 打包时确认。
